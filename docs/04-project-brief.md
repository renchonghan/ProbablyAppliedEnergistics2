# 立项一页纸（当前版本）

> 完整设计见 [05-current-design-decisions.md](05-current-design-decisions.md)；原版机器/生产链见 [06-vanilla-production-chains.md](06-vanilla-production-chains.md)。本文只保留一页能拍板的内容。

## 项目名

- 仓库：https://github.com/renchonghan/ProbablyAppliedEnergistics2
- 显示名：**可能是应用能源2 / Probably Applied Energistics 2**
- 声明：Unofficial fan mod, not affiliated with Questing Goose Studio, tinyBuild, or the Applied Energistics team.

## 一句话

给《深空当铺》做一套 **AE2 风格的机架式仓储 / 物流 / 订单自动化**：

> **3×3 机架阵列 + 3×3 核心设备 + PoE 干线 + 虚拟网络搬运 + 订单生产。**
> 线缆只带电、数据、调度；不做实体货运。

## 目标体验

- 玩家只负责下单：客户要什么、缺什么，点一下，机房自动拆单/备料/生产/送货；
- **AE 是总线，不是工厂**：网络只做存储/搬运/调度/监控；机器、农场、水/饲料/滤芯、电力线由玩家搭；
- 强兼：任何 inventory 可达的机器都能接；容器端点后续评估；tag/role/manual mapping，不写 per-machine proxy；
- 不用再逐个开箱子：控制终端是巨大的虚拟库存视图；
- 机柜阵列有真实空间成本：3×3 机架（内部 2×4 槽）、3×3 控制终端、1×1 模块/线缆；
- 接线有真实快乐：路径、容量、冗余、剪线、过载；
- 闭店后是黑灯工厂：配额生产、自动补货、早上报告。

## 硬件

- **Rack 3×3**：**扩展机器区**；外观 3×3，内部 **2 列 × 4 行 = 8 个万能槽**，UI 复用工具箱格子；可放原版机器（忽略形状）或 Disk Drive（3×3 算 1 bay）；PoE 端口/状态灯；相邻机架形成阵列；没插 ME 适配器的机器只是纯放置；防套娃，机架不能塞机架。
- **ME Controller 3×3**：网络大脑；一个网络一个；PoE 分配/能量缓冲/负载上限。
- **Control Terminal 3×3**：容器/终端；Storage 页 + Inbox 页 + Daily Plan 页（每日基础备料）。
- **Pattern Controller 3×3**：模板控制器；5 大页（参考原版储藏区（扩建）），每页 17×10；合成/过程模板 2×1，约 400 个；只有模板命中的输出耗尽后显示幽灵；不占频道。
- **Power Module 3×3**：巨型 UPS；16 电池槽 + 1 转换器槽；255 → 65,535 kJ；每天付账后只充一次；普通电池在线备电，无限电池只有日输出额度。
- **Disk Drive 3×3**：和机架同 footprint；内部 2×8 = 16 个磁盘槽；接固体/液体磁盘。
- **Solid / Fluid Disk 1×1**：两种独立磁盘；底座 16 索引 / 256 字节，材料强化到 512 / 65,535；各自独立容量/索引，升级保留内容。
- **Pattern 2×1**：合成模板记录输出+配方；过程模板记录输入条件+输出白名单（只读原版设置、只能 Endpoint）；样本不消耗；无配方/不可复现实例拒绝；放进模板控制器才生效。
- **Data Transfer Machine 3×3**：电池供电；磁盘对磁盘移动数据，换盘用。
- **Current Converter 1×1**：ME 能源柜专用插槽；输入**每日 kJ**；普通电池在线备电 + 日结单块最多充 1/4；无限电池无实时容量，日结读一次日输出额度（基础 12，+10/次，无上限，不缓存）。
- **每日结算**：电力预测先验算次日生产总耗电；无限电池吃 demand → 转换器补差 → 柜先满 → 电池逐块倒（单块 1/4 或满）；实际电网抽取记到**次日账单**。
- 16 电池槽**前到后**处理，不均摊；普通/无限/一次性/转换器按 tag 分类；一次性不充电，违禁品不搞超级科技。
- **ME Adapter 1×1（通用 Machine Endpoint）**：插机器电池槽；不可手动充电；插上且频道已连接才接管；默认 Endpoint（真实机器 push/pull/供电/monitor），Read-only 兜底；不虚拟产线；1 个 = 1 通道。
- **Planner**：订单只读规划，算材料/`cycles`/`currentKJ`/ETA；不产出、不能替代流水线。
- **端点发现**：机器 item 上 `ME_ENDPOINT_ROLE_MAP_STRING` → `MachineryPanelRow` role → 原版机器 profile → 手动映射 → 反射兜底；反射不猜语义。
- **Monitor**：Endpoint 的概况页，不是 profile；水培/RAS 显示水/营养/饲料/过滤或分离循环/鱼群/ETA/电/警报，固定阈值自动维护；RAS 按“组数 × 成体水需”预测爆缸。
- **ME Fractionation Array 3×3 / ME 分馏阵列**：固定 9 槽（布局 UV/M1/M2 · E1/P1/P2 · E2/P3/P4）；1 UV + 4 净水器 + 2 蒸发器 + 2 水分收集器；子机自动虚拟电池 max 65,535 + 严格边界；水/液体分馏（含药品前处理），物质守恒；成品药仍需加热板 + Chem Finisher。
- **Cable 1×1**：PoE 干线；电 + 数据 + 物流调度；不运物品；可剪线/过载。
- **频道**：1 个已连接 ME 适配器（Endpoint/Read-only）= 1 通道；常规 8 / 致密 32；机架统计内部适配器数量申请，按槽位顺序点亮；没抢到频道的适配器按未插处理。
- **Fluid Transfer Gun / 移液枪**：3×2 工具（同打标机），吸/加双模式；可放进工具箱用快捷键装备。

## 交互

- Storage 页：虚拟库存视图；角标显示数量/液体体积；0 库存**只有模板命中才显示幽灵**；合成/过程模板都排 Endpoint job，显示 ETA/缺料；没有模板的条目耗尽后直接消失。
- Inbox 页：真实容器页；扔进来立刻转移到 Storage；失败留在 Inbox 报错，不删除。
- 复杂物品入库自动拆解（枪/插件/容器）；不想拆就用真实盒子；原子/密封/任务物品拒绝虚拟存储。
- 带耐久/可变参数/永久强化/独特状态的物品（耐久工具、滤芯、电池、无限电池、容器内容物、固定新鲜度的荧光莓等）按**实例**存，一件一索引，不合并；序列化校验失败就拒绝。
- 机器可整机存盘，但存进去**停机**；进机架后，只有插 **ME 适配器**且频道已连接才被接管（Endpoint/Read-only）；没插/没频道只是纯放置。
- **Endpoint/Read-only 10 tps 对账**（MC 20 tps 的一半）：Endpoint 只搬白名单角色、原版 cycle 照跑；Read-only 不动；Planner 只读规划/预测；不推进生长、不做虚拟产物；只扫适配器机器，分批/round-robin。
- 带卡死模组的机器入库自动拆模组，从 ME 能源柜扣 **200KJ**；柜内不足就拒绝。
- 幽灵物品：**只来自模板命中**；`MayRemove=false`，上不了柜台；生产成功才写入磁盘条目（或真实槽模式）；无模板耗尽即消失，不占磁盘索引/字节。
- 快捷键：实测 Alt = 最前端窗口/容器 ↔ 柜台（无窗口时背包 ↔ 柜台）；Ctrl = 仓库 ↔ 最前端窗口（无窗口时上柜台）；柜台 = 交易区。打开控制终端时 `ToFront()`。

## 订单 / 自动合成

- **订单卡**：客户要 X / 库存缺 X → 一键下单 → 查模板/库存 → 拆配方 → 缺什么做什么 → 缺模板/机器/合适鱼/原料/电 → 报错 → 完成送柜台。
- **配额订单**：保持“水 30、餐 20、零件 10”，缺了自动补；与客户订单共用引擎。
- **夜间排产**：按周期算，**0 加急费**；基础电力照扣（执行时实时读机器 `cycleKJ`）；Endpoint 可免费 `BoostMachine`。例：4 铁锭若需 2 周期，每周期 3 矿石 + 2 kJ → 6 矿石 + 4 kJ。
- **白天加急**：每周期额外 **15 kJ**（涡轮加速器同价）+ 基础电力；Endpoint 触发 `BoostMachine`；过程模板只能 Endpoint ETA。
- **合成模板**：Endpoint push 输入 → 等 cycle → pull 输出；夜间 currentKJ（实时读机器能耗）、白天加急 +15 kJ/周期。
- **过程模板**：常驻屠宰按当前原版设置投喂；加急只选当前设置仍接受的最小鱼，**不改设置**；缺合适鱼显示“缺少材料”；输出格递归扫描自动收。
- **客户要求**：MVP 用独立订单控制台；后期 Harmony 嵌入客户界面。

## 里程碑（M0–M5）

- [ ] M0：3×3 控制终端容器 + 3×3 模板控制器 + 启动磁盘 + Storage/Inbox 页 + 2×1 模板 + 幽灵门控 + 事务式虚拟化/补货
- [ ] M1：3×3 机架（内部 2×4，8 个万能槽，能塞原版机器）+ 3×3 ME 控制器 + ME 适配器（Endpoint：role/tag/manual mapping）
- [ ] M2：3×3 电力模块 + 电流转换器 + 1×1 PoE 线缆 + 机架阵列 + 3×3 Disk Drive/磁盘 + 数据转移机
- [ ] M3：Planner（只读规划/ETA）+ 网络导入/导出 + 配额生产 + 即时补货 + 移液枪 + ME 分馏阵列 + 水培/RAS Monitor
- [ ] M4：订单系统 + 递归子订单 + 客户订单 + 过程模板/屠宰常驻/加急
- [ ] M5：手册/教程/平衡/创意工坊

## 非目标

- 不做实体货运/物品管道/物品飞行；
- 不做世界方块/线缆方块网格；
- 不做无模板自动生产；模板是幽灵/补货/订单的白名单；
- 不虚拟化水培/RAS/屠宰；活鱼/鱼苗/生长中植物不做虚拟存储；monitor 不做复杂控制台；
- 不做 per-machine proxy；默认 Endpoint；不做虚拟产线；
- 不靠反射猜输入/输出语义；反射只做兜底枚举/诊断；
- 不做 AE2 字节/类型 1:1 复刻；频道按原版 8/32；
- MVP **做虚拟化 + 入库拆解**：复杂物品拆成部件/内容物；原子/密封/任务物品拒绝，用真实盒子；
- 不改商店布局/核心循环/议价 UI；
- 不新增顾客精灵图/阵营；
- 不复制 AE2 代码/贴图/文本；
- 不把游戏反编译代码/本地化表提交到 GitHub。

## 技术底线

- 目标版本：Rev13 安装版（`0.46D`）；`<GameVersions>` 里写 `<Version>0.46</Version>`；Rev14 后再改 `1.0.0`。
- 能力：优先空 `<Capabilities />`；不用 native/dynamic-code/reflection-external/threads。
- 存档：先写盘后删、失败回滚、不生成 0 个真实物品、卸载可降级。
- 模板：2×1 物品；数据写 `itemState` tags（`SaveItemNode` 保存 tags，不保存 `itemFeatures`）；读回校验。
- 能耗：配方卡不存死；执行/预测时实时读机器 `cycleKJ`（强化/模块立即生效）。
- 端点发现：机器 item 上 `ME_ENDPOINT_ROLE_MAP_STRING` → `MachineryPanelRow` role → 原版 profile → 手动映射 → `ModReflect`/字面反射兜底；反射不猜语义。
- Monitor：RAS 水预算按“组数 × 成体水需”算；水箱固定 12L；10 tps 只搬白名单角色，UI 1 Hz 刷新。
- 无滤芯水循环：RAS 脏水 → 液体磁盘 → ME 分馏阵列（耗电）→ 纯水回灌；滤芯可选。
- 过程模板：只读 `AUTO_BUTCHER_*`，不写入/不覆写；只记录投喂条件和输出白名单；输出格递归扫描；触发方式 Phase 0 验证。
- 性能：缓存索引 + dirty 标记；不每帧全店扫描。

## 成功标准

- 玩家能在 30 秒内找到任意一件店内物品；
- modded 机器只要 inventory 可达，就能通过 tag/role/manual mapping 接进来；
- 玩家愿意为机柜/线缆/电力付钱；
- 客户要 X，点一下就能自动生产/送货；
- 模板能一次编码、长期复用；无模板物品耗尽后确实消失；
- RAS 鱼苗过多时，monitor 在缺水前报警；过程模板缺合适鱼时明确提示；
- 网络没有让鉴定/议价/检查变得无意义；
- 存档/读档/卸载不丢物品；
- F8 无异常、`mod-scan` 无拒绝项。
