# 立项一页纸（可填模板）

> 这是给“开始编排计划”用的一页纸。建议先把灰色占位符替换成你的决定，再据此写 GitHub README / 路线图。

## 项目名

- 仓库名：`ProbablyAppliedEnergistics2`（推荐，PascalCase，AE2 用全称）
- 显示名：**可能是应用能源2 / Probably Applied Energistics 2**
- 备选：`ProbablyAppliedEnergistics2Mod`、`StolenAppliedEnergistics2`、`AppliedEmporium2`、`DeepspaceAppliedEnergistics2`
- 声明：Unofficial fan mod, not affiliated with Questing Goose Studio, tinyBuild, or the Applied Energistics team.

## 一句话

在《深空当铺》里加入一套 **AE2 风格的仓储/物流网络**：把店内分散的柜台、背包、机器和存储单元变成一个可搜索、可过滤、可自动搬运（后期可自动合成）的“货流网络”。

## 目标体验

- 玩家不用再逐个打开箱子找货；
- 能用终端搜索/过滤/存取全店物品；
- 能用“链路/过滤器/优先级”把货自动送到该去的地方；
- 后期能“点一下，让网络把整条生产链补齐”；
- 网络设备要贵、要耗电/维护，不能 trivialize 鉴定、议价、违禁品检查。

## MVP（第一阶段，必须做）

- [ ] 网络控制器物品（网络 ID、能量/维护费、设备列表）
- [ ] 链接卡/链接 UI（把容器/机器加入网络）
- [ ] 终端自定义 UI：搜索、排序、过滤、取出/存入
- [ ] 容器适配器：玩家背包、前/后柜台、展示柜、机器窗口
- [ ] 过滤器 + 优先级（至少白名单 + 优先级）
- [ ] 存档/读档、错误处理、F8 日志
- [ ] 中英文本地化

**MVP 不做**：虚拟字节/类型、自动合成、频道拓扑、无线终端、P2P/量子/空间。

## 第二阶段（物流）

- [ ] 导入/导出链接物品
- [ ] 过滤器/保留量/顺序/优先级
- [ ] 日边界/夜间搬运
- [ ] 与 HopperHelper / Storage Coordinator 共存

## 第三阶段（自动合成）

- [ ] Pattern 物品/编码器
- [ ] 合成 CPU + job 队列
- [ ] 装配链接（绑定机器/容器）
- [ ] 只支持模组自定义配方或少量现有机器
- [ ] job 持久化/失败回滚

## 非目标（明确不做）

- 不改商店布局/核心循环/议价 UI；
- 不新增顾客精灵图/阵营；
- 不做世界方块/线缆网格；
- 不做 PvP/多人（除非游戏支持）；
- 不复制 AE2 代码/贴图/文本；
- 不把游戏反编译代码/本地化表提交到 GitHub。

## 技术底线

- 目标版本：**Rev13 安装版**（`0.46D`）/ 或 Rev14 beta（二选一，先写死）
- 清单：`<Version>0.46</Version>`（Rev13）或 `1.0.0`（Rev14）
- 能力：优先空 `<Capabilities />`；不用 native/dynamic-code/reflection-external/threads
- 存档：事务式搬运，先放后删；不丢物品；卸载可降级
- 性能：缓存索引 + dirty 标记；不每帧全店扫描

## 需要拍板的 10 个问题

1. 目标版本：Rev13 还是 Rev14 beta？
2. 范围：只做 MVP，还是一路做到自动合成？
3. 存储：物理单元还是虚拟字节/类型？
4. 频道：模拟负载限制，还是“无限但贵”？
5. 自动合成：只支持自定义配方，还是适配现有机器？
6. 美术：原版 Machinery 风格还是自定义？
7. 进度：用哪个人脉升级/夜间地点/掉落表解锁？
8. 语言：中英双语还是先中文？
9. 名字：`可能是应用能源2 / Probably Applied Energistics 2` 还是别的？
10. 发布：Steam 创意工坊还是 GitHub 手动安装？

## 成功标准

- 玩家能在 30 秒内找到任意一件店内物品；
- 玩家愿意为了网络设备付钱/付维护费；
- 网络没有让鉴定/议价/检查变得无意义；
- 存档/读档/卸载不丢物品；
- 模组在 F8 无异常、`mod-scan` 无拒绝项。
