# 当前设计决议（Current Design Decisions）

> **Status:** authoritative current direction, 2026-11-14.
> 本文覆盖 `03`/`04` 里与之冲突的探索性选项。`01` 是 AE2 参考，`02` 是游戏参考，`03` 是 API/可行性调查。

## 0. 一句话

**可能是应用能源2** 是给《深空当铺》的**机架式仓储 / 物流 / 订单自动化**：

> **3×3 机柜阵列 + PoE 干线 + 虚拟网络搬运 + 订单生产。**
> 线缆只负责电、数据、调度；**不做实体货运**。

## 2. 核心原则

1. **虚拟逻辑，不做实体货运**  
   有网 = 物品可寻址；搬运 = 直接库存事务；没有实体管道、没有物品飞行、没有每帧物流模拟。  
   AE2 在大服能活下来，就是因为它没有实体管道；我们照这个底层哲学做。

2. **线缆必须有，但线缆不运物品**  
   线缆是拓扑、供电、数据、物流调度；真正的物品在端点由模块直接搬。  
   玩家接线的快乐来自**路径、容量、冗余、剪线、过载**，不是看物品在管子里飞。

3. **空间是浪漫，不是菜单**  
   机架/ME 控制器/控制终端/电力模块都是 **3×3 真实物品**，固定占用基础空间；机架 bay 卡和线缆是 **1×1**。  
   机柜阵列排开、带灯、带端口、带线——这是 AE 玩家的浪漫。  
   不统一的异形格子才是华容道；统一的 3×3/1×1 是机房平面图。

4. **能用真实物品就用真实物品**  
   MVP 的存储底层可以是真实物品槽 + 自动补货，物品是实际的，拿走会空，mod 自动补。  
   这样存档、feature、纯度、真伪都由游戏原生逻辑处理，避免第一版就做虚拟序列化。

5. **自动化必须消耗资源**  
   补货/生产必须检查配方、原料、能量；不能凭空 clone。  
   否则就是无限复制机，房租、检查、经济全崩。

6. **订单是玩家唯一需要理解的东西**  
   玩家只负责下单；拆配方、备料、排队、生产、送货由机房完成。  
   AE2 的递归工单可以做，但要藏在“订单卡”后面。

## 3. 硬件形态

### 3.1 机架（Rack）

- **3×3 真实物品**，固定占用基础空间。
- 内部 **9 个 1×1 bay**（9U），每个 bay 插一个模块。
- 左/右 **PoE 端口**，状态灯。
- 机架有供电预算/负载/维护费。
- 相邻 3×3 机架形成 **Rack Array（机柜阵列）**；视觉上连成一排，可以有共享背板/管理加成，但每个机架仍然占 3×3。

### 3.2 ME 控制器（3×3）+ 控制终端（3×3）

- **ME Controller 3×3**：网络大脑；一个网络一个；负责 PoE 分配、能量缓冲、网络负载/端口上限。被拆/移走就断网。
- **Control Terminal 3×3**：容器/终端 UI；可以有多个；通过 PoE 连接控制器。
  - **Storage 页**：虚拟库存视图（搜索/过滤/取出/即产）；
  - **Inbox 页**：真实容器页，专门收投放，扔进来立刻转移走；
  - 后续可加 **Orders 页**（订单卡）。
- 控制器和终端分开，都是 3×3；这样机柜阵列里每一台都是同样的 footprint。

### 3.3 电力模块 / 能源输入（3×3）

- **3×3 真实物品**，负责 AE2 式“能源输入”：接受外部电力/电源物品/PoE，存成 kJ，供给网络。
- 有电池槽/电源端口；可以当作网络的 PSU。
- 供能矩阵/超频模块可以集成在这里，或作为 3×3 的独立升级件。
- 统一 3×3：机架、控制器、终端、电力模块排在一起，视觉上是一排整齐的机柜。

### 3.4 线缆（PoE Trunk，1×1）

- **1×1 真实物品**，物理摆在机架/控制器/终端/电力模块之间。
- PoE 干线 = **电 + 数据 + 物流调度**；**不运物品**。
- 有等级/容量/成本；可以剪断、改线、看负载。
- 过载 = 机架掉电/设备离线；冗余/双 uplink 有意义。
- 机房用 **uniform grid**（主要设备 3×3、线缆 1×1），不玩异形拼图。
- 具体放在基础背包还是专用机房页，Phase 0 定；无论哪种，空间成本保留。

### 3.5 机架内模块（1×1 bay cards）

| 模块 | 作用 |
|---|---|
| **Storage** | 统一槽位存储；物品一个槽一个（堆叠算一个），不按形状 |
| **Import** | 从外部容器/机器抽物品进网络 |
| **Export** | 把网络物品推到前台/展示柜/机器 |
| **Production** | 配方 + 目标配额 + 机器链接；驱动机器生产 |
| **Security** | 隐藏违禁品/赃物，但有检查风险 |

> 电力是 3×3 外部模块；控制终端是 3×3 外部设备；机架 bay 只放 1×1 功能卡，保持“机柜 + 板卡”的层次。

### 3.6 显性 Hero Items

| 物品 | 尺寸 | 角色 |
|---|---|---|
| **ME Controller / ME 控制器** | 3×3 | 网络大脑，一个网络一个 |
| **Control Terminal / 控制终端** | 3×3 | 容器/UI：Storage、Inbox、Orders |
| **Power Module / 电力模块** | 3×3 | 能源输入/PSU/供能矩阵 |
| **Rack / 机架** | 3×3 | 9 个 1×1 bay，插功能卡 |
| **PoE Cable / PoE 线缆** | 1×1 | 电 + 数据 + 调度，不运物品 |
| **Fluid Intake Gun / 吸液枪** | 1×1 tool | 从容器/机器吸液进网络 |
| **Fluid Fill Gun / 加液枪** | 1×1 tool | 从网络给容器/机器加液 |

### 3.7 吸液枪 / 加液枪（流体工具）

- 注册为 **TOOL**，兼容工具箱：放进 toolbox 的 3–9 号槽，用 1–9 快捷键装备，再对目标容器/机器使用。
- **吸液枪**：目标容器/机器 → 枪内储罐/网络；**加液枪**：枪内储罐/网络 → 目标容器/机器。
- 枪有内部储罐（ml）、液体类型、纯度/污染标记；可以在控制终端/Inbox 排空或补充。
- 可以给水培、净化器、水箱、反应器直接加液；也可以从顾客的容器里吸液（如果游戏允许）。
- 风险与乐子：
  - 加错液体/污染批次会掉品质；
  - 吸到违禁化学品/赃物液体可能被检查；
  - flavor text 建议写：**“本来是加油枪，现在给你加纯水。不要对顾客使用。”**
- 这是“显性物品”的一部分：玩家能记住“我有吸液枪/加液枪”，而不是只有抽象模块。

## 4. 控制终端交互

### 4.1 Storage 页

- 打开后是巨大的虚拟库存视图。
- 每个条目右下角角标：
  - 普通物品：`x12`；
  - 液体：`12.5 L` / `12,500 ml`；
  - 0：灰色 `0`，但条目仍然可点。
- 有货：左键取 1，右键取一组。
- 0：点击 = 消耗能量，**即刻生产**。
- 液体按**纯度/品质分行**，不要把不同纯度的水混成一个数字。
- 搜索/过滤/排序是 UI 层；底层可以是真实物品槽 + 自动补货。

### 4.2 Inbox 页（投放页）

- 一个**真实容器页**，专门收玩家扔进来的东西。
- 扔进来 → 自动转移到 Storage → 槽位清空。
- 转移失败（满/不可存/缺配方）→ 物品留在 Inbox，红色状态提示，**不删除**。
- 等于给控制终端装了一个“单向漏斗页”。
- 实现要原子：先确认目标接受，再从 Inbox 移除；转移中加短暂 lock，别让玩家 Alt 拿走，避免复制/丢失。

### 4.3 幽灵物品（Ghost Item）

- 0 库存显示**幽灵物品**，不是 0 个的真实物品。
- `mayInventoryRemoveItemFunc = false`，任何快捷键都拿不走；不会卡上柜台。
- 点击幽灵 → 触发生产；成功 → 替换成真实物品；失败 → 继续当幽灵，tooltip 报错。
- 幽灵物品不进 Inbox；它只存在于 Storage 页的“0 库存”条目。

### 4.4 快捷键（实测行为）

游戏实测（用户开游戏确认）：

| 键 | 行为 |
|---|---|
| **Alt** | 在最前端打开窗口/容器与柜台之间扔；没有打开窗口时，在仓库（背包）与柜台之间扔 |
| **Ctrl** | 在仓库与最前端打开窗口之间扔；没有打开窗口时，扔上柜台 |
| **柜台** | = 交易区 |

- 打开控制终端时把它 `ToFront()`，确保它是“最前端窗口”，Alt 的语义稳定是“面板 ↔ 交易区”。
- 真实物品走游戏原生 quick-move；幽灵物品锁死，不响应。
- 如果 Storage 页是自定义虚拟列表（不是真实 `GameItemElement`），就自己调用 `ModHelper.MoveItemToFrontCounter(item)` / `GraphUtils.TryAcceptOnce(...)` 复刻同样行为。
- 扔错地方无所谓：顶多进仓库，手一拖就回来。

### 4.5 自动补货

- 监听取出/消耗 → 触发补货。
- 补货必须：检查配方 → 检查原料 → 检查能量 → 成功才生成。
- 补货模式：
  - **能量即产**：有电有料，立刻补；
  - **夜间批产**：闭店后按配额补；
  - **自动补货开关**：每个条目单独开关。
- 补货目标/上限可设；避免玩家不想补的东西被补。

## 5. 订单与自动合成

### 5.1 订单卡

```
┌ 订单 #42 ─────────────────┐
│ 客户：Vera                 │
│ 要：3x 净水                │
│ 库存：1 / 3                │
│ 缺：2                      │
│ 可做：是（缺 1 个空瓶）     │
│ 预计：2 周期 / 40 kJ       │
│ [一键下单]  [加急]          │
└────────────────────────────┘
```

- **一键下单**：有料就做，没料就自动拆子订单。
- **加急**：花供能矩阵/涡轮加速器的 kJ，立刻完成一个周期。
- **失败**：明确告诉玩家缺机器、缺原料、缺电、缺配方。

### 5.2 三层结构

1. **配方卡（Recipe）**  
   `输入 → 输出`，绑定机器类型、时间、能耗。

2. **订单（Job）**  
   数量、期限、优先级；递归展开依赖；中间产物放网络里；子订单可并行。

3. **执行器（Machine / 供能矩阵）**  
   普通机器按周期跑；供能矩阵花 kJ 直接完成一个周期；没有机器就排队或报错。

### 5.3 配额生产 = 定时订单

- **客户订单**：一次性，做完结束；
- **配额订单**：保持“水 30、餐 20、零件 10”，缺了自动补；
- 两者共用同一个订单引擎，只是 `once` vs `repeat`。

### 5.4 实时性

- 商店侧没有实时机器 tick；机器是周期制。
- `MachineTurboBoosterAdv.BoostMachine()` 已经证明可以手动触发一个周期；供能矩阵可以照这个模式做。
- 机器空闲 + 有料 → 立刻开工；
- 供能矩阵充好 → 秒一个周期；
- 没电/没机器 → 排队，订单卡显示 ETA；
- 闭店后 → 批量跑，早上报告“完成/缺料/缺电”。

### 5.5 客户要求

- 客户要的东西、采购委托、枪匠订单，都可以变成“客户订单卡”；
- 玩家在控制终端/订单页点一下；
- 做完自动送到柜台/委托槽；
- MVP 用独立订单控制台；后期可用 Harmony 在客户议价界面加“一键下单”按钮。

## 6. 网络 / PoE

- **PoE 干线** = 电 + 数据 + 物流调度命令；**没有物品包**。
- 机架/控制终端/线缆组成网络图；线缆剪断 = 网络断开。
- 容量模型（不做 AE2 频道/字节）：
  - **电力预算（kW/kJ）**；
  - **数据/端口数**；
  - **物流负载**（同时执行的订单/模块数）。
- 过载 = 设备离线/掉电；冗余/双 uplink 有意义。
- 后期可加子网/VLAN、无线终端、跨区链路；不做 P2P/量子/空间存储的 1:1 复刻。

## 7. 非目标（明确不做）

- **不做实体货运/物品管道/物品飞行**；
- 不做世界方块/线缆方块网格；
- 不做 AE2 的频道/字节/类型 1:1 复刻；
- MVP 不做虚拟库存序列化（先用真实物品 + 自动补货）；
- 不改商店布局/核心循环/议价 UI；
- 不新增顾客精灵图/阵营；
- 不复制 AE2 代码/贴图/文本；
- 不把游戏反编译代码/本地化表提交到 GitHub。

## 9. 技术落点

| 需求 | 可用 API / 做法 |
|---|---|
| 3×3 机架物品形状 | `SetSpriteAndShapeFromMod` / `SetSpriteAndShape` |
| 9 个 1×1 bay | 9 个 `GameSlotInventory` + `MachineHelper.Panel` / `MachineryTabs` |
| 控制终端容器 | `item.SetContentWindow(window)`；Storage/Inbox 分页 |
| 幽灵物品锁定 | `mayInventoryRemoveItemFunc = false`；`MayRemove()` 会被 quick-move 检查 |
| 取出/上交易区 | 真实物品走原生 quick-move；自定义列表调用 `ModHelper.MoveItemToFrontCounter` / `GraphUtils.TryAcceptOnce` |
| Inbox 自动转移 | `onSlotAddItemFunc` / 轮询；原子转移 + 短暂 lock；失败保留 |
| 自动补货 | 监听槽位移除；检查配方/原料/能量；成功才生成 |
| 即时完成周期 | `MachineTurboBoosterAdv.BoostMachine()` 思路：调用机器的 `onCycleEnd*`；模组配方直接执行 |
| 能量存储 | `power_source_item` / kJ 标签；Power 模块/供能矩阵 |
| 订单队列 | modData（JSON）+ 协程/日边界 tick；不要每帧全店扫描 |
| 网络索引 | 缓存 + dirty 标记；按 `uniqueId` 引用容器/机架 |
| 存档安全 | 先放后删；失败回滚；不生成 0 个真实物品；卸载降级 |

## 10. 开放问题

1. 目标版本：Rev13 安装版，还是 Rev14 beta？
2. 机架/线缆放**基础背包网格**，还是**专用机房页**？（空间成本都要保留）

## 11. 一句话收尾

> **玩家负责下单，机房负责干活。**
> 3×3 机柜阵列是浪漫，PoE 线缆是浪漫，虚拟搬运是性能，订单系统是自由。
