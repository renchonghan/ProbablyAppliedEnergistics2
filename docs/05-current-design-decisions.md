## 0. 一句话

**可能是应用能源2** 是给《深空当铺》的**机架式仓储 / 物流 / 订单自动化**：

> **3×3 机架阵列 + 3×3 核心设备 + PoE 干线 + 虚拟网络搬运 + 订单生产。**
> 线缆只负责电、数据、调度；**不做实体货运**。

## 2. 核心原则

1. **虚拟逻辑，不做实体货运**  
   有网 = 物品可寻址；搬运 = 直接库存事务；没有实体管道、没有物品飞行、没有每帧物流模拟。  
   AE2 在大服能活下来，就是因为它没有实体管道；我们照这个底层哲学做。

2. **线缆必须有，但线缆不运物品**  
   线缆是拓扑、供电、数据、物流调度；真正的物品在端点由模块直接搬。  
   玩家接线的快乐来自**路径、容量、冗余、剪线、过载**，不是看物品在管子里飞。

3. **空间是浪漫，不是菜单**  
   ME 控制器/控制终端/电力模块/磁盘驱动器是 **3×3 真实物品**；机架也是 **3×3 外观，内部 2 列 × 4 行 = 8 槽**；功能卡、磁盘、线缆是 **1×1**；原版机器进机架后槽内忽略形状。  
   机柜阵列排开、带灯、带端口、带线——这是 AE 玩家的浪漫。  
   不统一的异形格子才是华容道；统一的 3×3/1×1 是机房平面图。

4. **虚拟磁盘只存“可拆解后的叶子物品”**  
   入库 = 拆解计划 → 写盘 → 校验 → 删除原物品；失败不删除原件。  
   枪/带插件/容器等复杂物品**自动拆成部件/内容物**；不想拆就用真实盒子，不要扔进虚拟存储。  
   原子/密封/任务物品直接拒绝虚拟存储，提示“请用真实容器”。

5. **自动化必须消耗资源**  
   补货/生产必须检查配方、原料、能量；不能凭空 clone。  
   否则就是无限复制机，房租、检查、经济全崩。

6. **订单是玩家唯一需要理解的东西**  
   玩家只负责下单；拆配方、备料、排队、生产、送货由机房完成。  
   AE2 的递归工单可以做，但要藏在“订单卡”后面。

## 3. 硬件形态

### 3.1 机架（Rack）——扩展机器区

- **3×3 真实物品**，固定占用基础背包网格；内部孔位是 **2 列 × 4 行（8 槽）**；UI 类似工具箱的格子。
- 内部 **8 个万能槽（universal bays）**，不是 8 个 1×1 格子：
  - 每个槽可以放**一台原版机器**（不管它原本是 3×2 还是 2×2，槽内忽略形状）；
  - 也可以放一张 **1×1 功能卡**（Import/Export/Production/Security）。
- 机架就是“扩展机器区”：原版机器塞进去就能被网络供电/喂料/收产物，同时保留它自己的窗口和周期逻辑。
- 机器存进磁盘 = **停机归档**；放回机架也只是“放置架”，除非电池槽插了 **ME 适配器**。
- **只有插了 ME 适配器的机架机器才算 ME 虚拟机**；没插的机器网络完全不管，纯放置/手动使用。
- 左/右 **PoE 端口**，状态灯；机架有供电预算/负载/维护费。
- **一个机架 = 一个通道**；常规线 8、致密线 32（AE2 原版）。
- 相邻 3×3 机架形成 **Rack Array（机柜阵列）**；视觉上连成一排，可以有共享背板/管理加成，但每个机架仍然占 3×3。

### 3.2 ME 控制器（3×3）+ 控制终端（3×3）

- **ME Controller 3×3**：网络大脑；一个网络一个；负责 PoE 分配、能量缓冲、网络负载/端口上限。被拆/移走就断网。
- **Control Terminal 3×3**：容器/终端 UI；可以有多个；通过 PoE 连接控制器。
  - **Storage 页**：虚拟库存视图（搜索/过滤/取出/即产）；
  - **Inbox 页**：真实容器页，专门收投放，扔进来立刻转移走；
  - **Daily Plan 页**（每日基础备料；客户一次性订单后期再加）。
- 控制器和终端分开，都是 3×3；这样机柜阵列里每一台都是同样的 footprint。

### 3.3 电力模块 / ME 能源柜（3×3，巨型 UPS）

- **3×3 真实物品**，存 kJ，供给网络。
- **16 个普通电池槽 + 1 个电流转换器专用槽**。
- 电池行为：
  - **普通电池**：在线备电；柜内 kJ 不够时，直接扣电池的电；每日结算可充电，**单块最多充总容量的 1/4**（防超级快充偷鸡）。
  - **无限电池**：**没有实时容量**，只有“每天能出多少电”的**日输出额度**（`HYPERTECH_BATTERY_OUTPUT_INT`）：基础 **12**，强化一次 **+10**，**无上限**；睡觉结算时读一次当前值，玩家当天强化过就按新值算；**不缓存**；只参与日结，白天不放电。
- **有且只有一次充电机会：每天付账后**；白天不能补电。
- 柜容量：默认 **255 kJ**，可强化到 **65,535 kJ**（巨大 UPS）。
- 电流转换器面板设置“每日输入 kJ”；到账日抽这么多电存进柜里。
- 电用完 → 机器停；没有欠费账本。
- 统一 3×3：控制器、终端、电力模块、磁盘驱动器排在一起，视觉上是一排整齐的机柜。
- **槽位检查**：原版电流转换器和电池都属于 `power_source_item`，所以：
  - 转换器槽只接受 `CURRENT_CONVERTER_TAG`；
  - 16 个电池槽只接受 `power_source_item` 且**不是**电流转换器；
  - 用 `mayInventoryAddItemFunc` 分流，避免电池插进转换器槽/转换器占电池槽。

### 3.4 线缆（PoE Trunk，1×1）

- **1×1 真实物品**，物理摆在机架/控制器/终端/电力模块/磁盘驱动器之间。
- PoE 干线 = **电 + 数据 + 物流调度**；**不运物品**。
- 有等级/容量/成本；可以剪断、改线、看负载。
- 过载 = 机架掉电/设备离线；冗余/双 uplink 有意义。
- 机房用 **uniform grid**（机架外观 3×3、内部 2×4 槽；核心设备 3×3；线缆/功能卡/磁盘 1×1），不玩异形拼图。
- **已定**：放在基础背包网格；不是专用机房页。空间成本保留。

### 3.5 机架槽位（universal bays）

| 槽位内容 | 说明 |
|---|---|
| **原版机器** | 任意机器物品，槽内忽略形状；保留自己的窗口/周期/配方 |
| **Import 模块** | 从外部容器/机器抽物品进网络 |
| **Export 模块** | 把网络物品推到前台/展示柜/机器 |
| **Production 模块** | 配方 + 目标配额 + 机器链接；驱动机器生产 |
| **Security 模块** | 隐藏违禁品/赃物，但有检查风险 |

> 机架是“机器扩展区”，不是磁盘架：磁盘插在独立的 **Disk Drive** 里。  
> 机架 8 个万能槽可以混装机器和 1×1 功能卡；机器不按形状占位，避免原版机器把机架变成华容道。  
> 技术上：槽位用 `GameSlotInventory`（单槽容器，不按网格形状检查）；机器仍然在商店物品图里，`onCycleEnd*` 等周期回调照常跑。

### 3.6 磁盘驱动器（Disk Drive，3×3）

- **3×3 真实物品**，像 AE2 的 ME Drive：内部 **9 个磁盘槽**，每个槽插一张 **1×1 磁盘**。
- 磁盘分两种：
  - **Solid Storage Disk / 固体磁盘**：物品条目；512 索引 / 65,535 字节；
  - **Fluid Storage Disk / 液体磁盘**：液体条目；512 索引 / 65,535 字节。
- 驱动器把磁盘接入网络；控制终端的 Storage 页显示所有磁盘的聚合索引。
- 磁盘是 1×1 物品；驱动器是 3×3，保持机柜阵列统一 footprint。

#### 字节与索引（已定）

- **固体**：8 个物品 = 1 byte；一组 64 = 8 bytes（AE2 味）。
- **液体**：100 ml = 1 byte；1 L = 10 bytes（可控，不做无限水库）。
- 65,535 bytes ≈ 524,280 个物品，或 ≈ 6,553 L 液体；后续可调，但先按这个走。
- **索引**：固体 = `identifier + 关键 feature 签名`；液体 = `类型 + 纯度档位`（1%/5% 一档，避免无限索引）。
- **没有原子分离机时，不同纯度/混合液体不合并**：各自是实例/条目，512 索引自己承担。
- 有原子分离机后，入库自动分离/合并，按下文物质守恒规则结算。

#### 原子分离机（Atomic Separator，3×3）

- **3×3 Hero 设备**；液体、混合液、带纯度的固体（奥克莫西、梦尘等）都能拆。
- 可以插原版的 **效率 / 质量 / 速度模组** 强化；具体换算待定，但**效率模组会大幅降低耗电**。
- **没有分离机**：纯度物质不合并，各自占索引/实例。
- **有分离机**：每次存入自动分离，消耗电量；纯物质合并，剩余纯度留一个余数固体，杂质变液体原料。
- **物质守恒**（纯度用整数 0–100 计算，避免浮点漂移）：
  - `totalPure = Σ purity_i`，`n` = 输入件数；
  - `full = totalPure / 100`，`rem = totalPure % 100`；
  - `impurity = n * 100 - totalPure`；
  - `rem > 0`：输出 1 个纯度为 `rem` 的余数固体，吸收 `min(100 - rem, impurity)` 的杂质；剩余杂质 → 液体；
  - `rem == 0`：全部杂质 → 液体。
- 例子：
  - **3×75%** → `2×100%` + `1×25%` + `0 L` 杂质；
  - **4×75%** → `3×100%` + `1000 ml` 杂质液体；
  - **3×50%** → `1×100%` + `1×50%` + `1000 ml` 杂质液体。
- 1 单位杂质默认 = **1000 ml**（可调）；杂质都能装瓶，连淀粉也算液体，进液体磁盘单独存。
- 名字：**原子分离机 / Atomic Separator**；你叫“原子分离剂机”也行。

### 3.7 数据转移机（Data Transfer Machine，3×3）

- **3×3 真实物品**，带电池槽 + 两个磁盘槽。
- 用途：**磁盘对磁盘搬数据**，换硬盘/迁移/整理时用。
- 原则：**移动，不是复制**；源盘条目成功写入目标盘后才删除源条目，失败不丢数据。
- 消耗电池 kJ；理论用不到，但换盘/扩容时很舒服。
- 3×3 统一尺寸，和驱动器/机架排在一起。

### 3.9 移液枪（流体工具，3×2）

- **3×2**，和打标机（Labeler）同款 footprint；不是 1×1 小卡片，是一把真工具。
- 注册为 **TOOL**，兼容工具箱：放进 toolbox 的 1–9 号槽（**初始解锁 3 个，最多 9 个**），用 1–9 快捷键装备，再对目标容器/机器使用。
- 一把枪两个模式：**吸液**（目标容器/机器 → 枪内储罐/网络）和 **加液**（枪内储罐/网络 → 目标容器/机器）；右键/快捷键切换。
- 如果更喜欢仪式感，也可以拆成两把 3×2 的吸液枪/加液枪；两者都保持打标机尺寸。
- 枪有内部储罐（ml）、液体类型、纯度/污染标记；可以在控制终端/Inbox 排空或补充。
- 可以给水培、净化器、水箱、反应器直接加液；也可以从顾客的容器里吸液（如果游戏允许）。
- 风险与乐子：
  - 加错液体/污染批次会掉品质；
  - 吸到违禁化学品/赃物液体可能被检查；
  - flavor text 建议写：**“本来是加油枪，现在给你加纯水。不要对顾客使用。”**
- 这是“显性物品”的一部分：玩家能记住“我有吸液枪/加液枪”，而不是只有抽象模块。

### 3.10 ME 适配器（1×1，电池槽；原 AE 转换模组）

- **1×1**，和电池同类型，插进机器的电池槽。
- **唯一作用：把机架上的机器标记为 ME 虚拟机**；没插适配器的机器只是纯放置架，网络不管。
- **不可手动充电**，不是玩家电池；65,535 只是内部缓冲/兼容值，用来满足游戏电池槽的供电检查。
- 机器存磁盘 = 停机归档；插了适配器 + 在机架 = 虚拟产线，但**真机器不跑 cycle**：
  - 机器输入/输出里的东西由 proxy 扫描后**直接挪进磁盘**；
  - 生产/合成由 mod 按配方 + 机器属性**直接计算**，不调用 `onCycleEnd*`、不靠机器自己干活；
  - 能耗从 ME 能源柜扣；能源不够 → 本周期不跑。
- 机器本身只是“能力 token”：提供配方类型、强化模组、效率/质量/速度等属性；网络同步这些属性后虚拟计算。
- flavor text：**“ME 适配器。插上，机器就变成一张生产许可证。”**

### 3.11 电流转换器（1×1，ME 能源柜专用插槽）

- **1×1**，插在 ME 能源柜的**专用插槽**，不占机器电池槽。
- **输入功率 UI**（类似鉴定价值界面）：输入的是**每日 kJ**，不是即时功率。
- **每日结算**：每天付账后，抽 `dailyKJ` 存进能源柜，上限 = 柜容量（255 → 65,535）。
  - **普通电池**：每日结算可充电，单块最多充总容量的 **1/4**；白天柜内不够时也**直接扣电池**（在线备电）。
  - **无限电池**：没有实时容量，只有日输出额度（基础 12，强化 +10/次，无上限）；睡觉结算时读一次当前额度（当天强化也生效），**不缓存**；只参与日结，白天不放电。
  - 没有电池：按 `dailyKJ` 从店内电力/账户结算，走 `CURRENT_CONVERTER_SERVICE`/每日电费。
- **日结算法（先验，倒红酒）**：
  1. proxy 镜像机器状态，先验算出次日生产总耗电 `demand`；
  2. **无限电池按日输出额度先吃 demand**（睡觉结算时读一次当前额度；当天强化按新值；不缓存）；
  3. demand 超过无限电池 → **电流转换器补差额**，转换器 `dailyKJ` 相应减少；
  4. 转换器剩余预算：**先把 ME 能源柜补满**；
  5. 柜满后，**挨个给充电电池倒电**：单块本次最多充 `总容量 × 1/4`，或者直接倒满，先到先停；有剩余预算继续下一块；
  6. 记录转换器**实际从电网抽取的 kJ**；这笔账单**次日结算**。
- **250 例子**：无限电池日额度 200，全部用掉；转换器补 50；剩 150 → 柜子缺 100（满），充电电池 700/800 再倒 50 → **750/800**；转换器实际抽 **200**，次日账单 200。
- **150 例子**：无限电池日额度 200，用掉 150（剩 50 日额度，不是容量）；转换器抽 150 → 柜子缺 100（满），再给充电电池倒 50 → **750/800**；次日账单 150。
- 账单 = `dailyKJ` × 当前转换率；复用 `CurrentConverterHelper` 的 rate/日结逻辑。
- 如果 `dailyKJ` > 柜容量：UI 直接限制/提示；如果电源不足：按可用量充，显示缺口。
- **200KJ 卡死模组罚金**也从 ME 能源柜扣；柜内不足 200KJ → 拒绝拆解/入库。
- 机器/机架白天只吃能源柜，不再逐台找店电；能源柜一天就这一口电。

#### 16 个电池槽：顺序与分类

- **顺序**：从前往后（slot 0 → 15），**不搞均摊**；抽电和充电都是前到后。
- **充电（倒红酒）**：每块最多充 `总容量 × 1/4` 或直接倒满；预算空了，后面的电池没得喝。
- **电池分类（按 tag）**：
  - **可充电普通电池**：`power_source_item` 且不是 disposable/hypertech/converter；在线备电；日结可充，单块 1/4 或满。
  - **无限电池**：`HYPERTECH_BATTERY_TAG`；没有实时容量，只有日输出额度；日结读一次；不参与普通充电/在线放电。
  - **一次性电池**：`POWER_SOURCE_ITEM_DISPOSABLE_TAG`；只放电、不充电；违禁品标记不改变物理，不生成无限电。
  - **电流转换器**：`CURRENT_CONVERTER_TAG`；只进专用槽，不进 16 电池槽。
- **防超级科技**：违禁品/一次性电池不得被当成无限电池或可充电电池；未知电池类型 → 拒绝充电，最多按一次性放电处理。

## 4. 控制终端交互

### 4.1 Storage 页

- 打开后是巨大的虚拟库存视图。
- 每个条目右下角角标：
  - 普通物品：`x12`；
  - 液体：`12.5 L` / `12,500 ml`；
  - 0：灰色 `0`，但条目仍然可点。
- 有货：左键取 1，右键取一组。
- 0：点击 = 消耗能量，**即刻生产**。
- 液体按**纯度/品质分行**，不要把不同纯度的水混成一个数字。
- 搜索/过滤/排序是 UI 层；底层是磁盘条目（虚拟存储），不是真实物品槽。
- 物品入库 = 拆解计划 + 快照 → 写盘 → 校验 → 删除原物品；0 库存显示幽灵条目。

### 4.2 Inbox 页（投放页）

- 一个**真实容器页**，专门收玩家扔进来的东西。
- 扔进来 → 生成拆解计划/快照 → 写入磁盘 → 校验 → 删除原物品 → 槽位清空。
- 转移失败（满/不可存/缺配方/序列化失败）→ 物品留在 Inbox，红色状态提示，**不删除**。
- 等于给控制终端装了一个“单向漏斗页”。
- 实现要原子：先写盘成功，再从 Inbox 删除；转移中加短暂 lock，别让玩家 Alt 拿走，避免复制/丢失。

#### 入库拆解规则

- **简单物品**：1 个条目。
- **枪/带插件**：拆成枪身、枪管、弹匣、枪托、下挂、特殊槽等；每个部件独立条目。
- **容器/背包**：内容物递归入库；空容器作为独立条目（或按规则返回）。
- **液体容器**：液体进液体磁盘，空容器进固体磁盘；混合液先是一个“混合液”条目，原子分离机再拆。
- **机器**：不拆，整机 Instance 存；存进去不工作、不耗电；要成为 ME 虚拟机必须放进机架 + 插 **ME 适配器**。
- **原子/密封/任务物品**：拒绝虚拟存储，提示“请用真实盒子/容器”，不要强行 snapshot。
- **卡死模组**：带 `MODULE_STUCK_TAG` 的机器入库时自动拆模组，**从 ME 能源柜扣 200KJ**；柜内不足 200KJ 就拒绝，防免费拆 bug。
- **不想拆**：把东西放真实盒子/背包，不要扔进 Inbox；虚拟存储不保留复杂物品树。
- **拆解预览/日志**：Inbox 显示“将拆成 N 个条目”；任一步失败都不删除原件。
- **价值**：部件按游戏原值；不复制价值、不凭空生成，拆解是玩家选择。

### 4.3 幽灵物品（Ghost Item）

- 0 库存显示**幽灵物品**，不是 0 个的真实物品。
- `mayInventoryRemoveItemFunc = false`，任何快捷键都拿不走；不会卡上柜台。
- 点击幽灵 → 触发生产；成功 → 写入磁盘条目（或生成真实物品，如果该条目是真实槽模式）；失败 → 继续当幽灵，tooltip 报错。
- 幽灵物品不进 Inbox；它只存在于 Storage 页的“0 库存”条目。

### 4.4 快捷键（实测行为）

游戏实测（用户开游戏确认）：

| 键 | 行为 |
|---|---|
| **Alt** | 在最前端打开窗口/容器与柜台之间扔；没有打开窗口时，在仓库（背包）与柜台之间扔 |
| **Ctrl** | 在仓库与最前端打开窗口之间扔；没有打开窗口时，扔上柜台 |
| **柜台** | = 交易区 |

- 打开控制终端时把它 `ToFront()`，确保它是“最前端窗口”，Alt 的语义稳定是“面板 ↔ 交易区”。
- **Inbox 页/真实物品**：游戏原生 quick-move 生效。
- **Storage 页虚拟条目**：自定义列表，需要在点击处理里自己复刻 Alt/Ctrl；幽灵物品锁死，不响应。
- 如果 Storage 页是自定义虚拟列表（不是真实 `GameItemElement`），就调用 `ModHelper.MoveItemToFrontCounter(item)` / `GraphUtils.TryAcceptOnce(...)` 复刻同样行为。
- 扔错地方无所谓：顶多进仓库，手一拖就回来。

### 4.5 自动补货

- 监听取出/消耗 → 触发补货。
- 补货必须：检查配方 → 检查原料 → 检查能量 → 成功才写入磁盘条目。
- 补货模式：
  - **能量即产**：有电有料，立刻补；
  - **夜间批产**：闭店后按配额补；
  - **自动补货开关**：每个条目单独开关。
- 补货目标/上限可设；避免玩家不想补的东西被补。

### 4.6 实例物品与校验（不能合并）

> **这不是 edge case，这是“合并了会被玩家打”的 case。**

典型例子：**无限强化电池**（`HypertechBatteryHelper`）：

- `HYPERTECH_BATTERY_TAG`；
- `HYPERTECH_BATTERY_OUTPUT_INT`（基础 **12**，每次强化 +10）；
- `HYPERTECH_BATTERY_UPGRADE_COUNT_INT`（强化次数）；
- 还能继续叠 `unitValue`。

如果把这种电池当成普通“物品类型”合并，所有电池会变成一个条目，强化等级直接蒸发。必须按**实例**存：

| 存储类别 | 规则 |
|---|---|
| **Type-stackable** | 简单可堆叠物品；同 `ItemKey` 合并数量 |
| **Instance** | 有永久强化/改装/序列号/独特状态的物品；**一件一个索引**，完整快照，不合并。机器也走 Instance（整机、含电池槽/模块），存盘后**停机** |
| **Refuse** | 原子/密封/任务/未知模组物品，或快照校验失败；拒绝虚拟存储，用真实盒子 |

规则：

- 任何带永久强化 tag 的物品（`HYPERTECH_BATTERY_*`、`MACHINE_*`、`MODULE_*`、`TURBO_*`、`CURRENT_CHARGE_TAG`、`power_source_item_*` 等）→ **Instance**，一件一个索引。
- **机器**：不拆，整机 Instance 存；存进去不工作、不耗电；要成为 **ME 虚拟机**必须放进**机架** + 插 **ME 适配器**。快照包含电池槽/模块；快照失败就拒绝。
- `Instance` 条目保存：`identifier`、`unitCount`、全部 tag、`itemFeatures`、`itemTypes`、`unitValue`、`lateUnitValue`、`shape/state`、子物品（仅机器）等；数值用精确类型，不截断。
- **入库校验**：序列化 → 反序列化成临时物品 → 对比实例签名（所有 tag/feature/数值/子物品）；不一致就拒绝，原件留在 Inbox，提示“请用真实盒子”。
- **保守默认**：只有白名单里的简单物品允许 Type-stackable；其余一律 Instance 或 Refuse。宁可拒绝，不可静默合并。
- 512 索引是硬上限；每个独特电池/机器占 1 个索引，装不下就换磁盘或放真实盒子。

## 5. 订单与自动合成

### 5.1 订单卡

```
┌ 订单 #42 ─────────────────┐
│ 客户：Vera                 │
│ 要：3x 净水                │
│ 库存：1 / 3                │
│ 缺：2                      │
│ 可做：是（缺 1 个空瓶）     │
│ 预计：2 周期 / 40 kJ       │
│ [一键下单]  [加急]          │
└────────────────────────────┘
```

- **一键下单**：有料就做，没料就自动拆子订单。
- **加急**：花供能矩阵/涡轮加速器的 kJ，立刻完成一个周期。
- **失败**：明确告诉玩家缺机器、缺原料、缺电、缺配方。

### 5.2 三层结构

1. **配方卡（Recipe）**  
   `输入 → 输出`，绑定机器类型、时间、能耗。

2. **订单（Job）**  
   数量、期限、优先级；递归展开依赖；中间产物放网络里；子订单可并行。

3. **执行器（ME 虚拟机 / 供能矩阵）**  
   ME 虚拟机按配方 + 属性直接计算；非虚拟机器才按周期跑；供能矩阵花 kJ 加速/完成计算；没有机器就排队或报错。

### 5.3 配额生产 = 定时订单

- **客户订单**：一次性，做完结束；
- **配额订单**：保持“水 30、餐 20、零件 10”，缺了自动补；
- 两者共用同一个订单引擎，只是 `once` vs `repeat`。

### 5.4 实时性

- 商店侧没有实时机器 tick；ME 虚拟机也不跑真机器周期，直接走计算。
- `MachineTurboBoosterAdv.BoostMachine()` 只用于非虚拟机器/兼容路径；ME 虚拟机用供能矩阵加速**虚拟计算**。
- 配方 + 原料 + 机器属性齐了 → 立刻算出产物；
- 供能矩阵充好 → 加速计算/瞬间完成；
- 没电/没机器/缺配方 → 排队，订单卡显示 ETA；
- 闭店后 → 批量计算，早上报告“完成/缺料/缺电”。

### 5.5 每日计划（Daily Plan）

- 控制终端独立一页 **Daily Plan**：设定明天每种货的目标库存（水 30、餐 20、零件 10……）。
- 闭店/夜间按计划补货/生产；早上报告完成/缺料/缺电。
- 客户采购、枪匠订单可以复用同一个 job 引擎，但**MVP 先做每日基础备料**，一次性客户订单后期再加。
- 后期可用 Harmony 在客户议价界面加“一键下单”按钮，但不是 MVP 主入口。

### 5.6 ME 虚拟机（只认 ME 适配器）+ 1 Hz 对账

- **只有插了 ME 适配器的机架机器才是 ME 虚拟机**；没插的机器纯放置，网络完全不扫描、不锁 UI。
- **1 秒对账一次**，只扫带适配器的机器：
  - 机器生产输入/输出槽里的东西，看到就**直接挪进磁盘**；
  - 电池、模块、工具等内部槽**不动**；
  - 不删除、不吞物品；未知机器布局只写日志。
- **生产/合成纯计算**：机器只是能力 token，提供配方类型、强化模组、效率/质量/速度；网络按配方 + 属性直接算出产物，**不跑真机器 cycle**，也不调用 `onCycleEnd*`。
- 同步机器属性：强化模组、配置 tag、效率/质量/速度等；玩家改机器配置后，下次 1 Hz 同步生效。
- **不做“虚拟副本生产”**：没有第二台虚拟机器在跑；真机器只是被读取/清空/计算，产物由网络写入磁盘。

## 6. 网络 / PoE

- **PoE 干线** = 电 + 数据 + 物流调度命令；**没有物品包**。
- **频道按 AE2 原版**：**1 个机架 = 1 个通道**；常规线 8，致密线 32。  
  不做轮椅：31 个机架可以，33 个就请加线/加控制器，不能一根线无限挂。
- **频道不够 = 罢工**：分不到通道的机架和断电同级，整架离线、机器停、状态灯红；不会“降速运行”。
- 机架/控制终端/线缆组成网络图；线缆剪断 = 网络断开。
- 电力预算/物流负载另算，不跟频道混：
  - 电力决定机架能不能跑；
  - 频道决定能挂多少机架；
  - 物流负载决定同时跑多少订单。
- 过载 = 设备离线/掉电；冗余/双 uplink 有意义。
- 后期可加子网/VLAN、无线终端、跨区链路；不做 P2P/量子/空间存储的 1:1 复刻。

## 10. 决策记录（已定 / 待定）

### 已定

- **目标版本**：先做 Rev13 安装版（`0.46D`）；Rev14 beta 以后再说。
- **放置**：机架/线缆放**基础背包网格**；不是专用机房页。空间成本保留。
- **机架**：外观 **3×3**，内部 **2 列 × 4 行 = 8 个万能槽**；槽位分 2/4/6/8 等级，最多 8；UI 类似工具箱。
- **频道**：1 个机架 = 1 个通道；常规线 **8**，致密线 **32**（AE2 原版，不做轮椅）；分不到通道的机架**直接罢工停机**，不降速。
- **字节**：固体 **8 个 = 1 byte**；液体 **100 ml = 1 byte**；磁盘 512 索引 / 65,535 bytes。
- **入库拆解**：枪/容器等复杂物品自动拆；机器整机 Instance 存但停机；原子/密封/任务物品拒绝，用真实盒子。
- **卡死模组**：带 `MODULE_STUCK_TAG` 的机器入库时自动拆模组，**从 ME 能源柜扣 200KJ**；柜内不足就拒绝；预付费/电流转换器实现 Phase 0 确认。
- **ME 虚拟机**：只有插 **ME 适配器**的机架机器才被网络接管；没插 = 纯放置，不扫描、不锁 UI。适配器机器 **1 Hz 对账**，输入/输出物品直接挪磁盘；**生产/合成纯计算**，不跑真机器 cycle、不调用 `onCycleEnd*`；电池/模块/工具槽不动；不做虚拟克隆。
- **每日计划**：控制终端单独一页 **Daily Plan**，做每日基础备料；客户一次性订单后期再加。
- **原子分离机**：只影响液体/纯度物质；没有它不允许合并；有它后入库自动分离并耗电；物质守恒，杂质进液体磁盘。
- **电力合同**：ME 能源柜 **16 电池槽 + 1 电流转换器槽**，容量 255 → 65,535 kJ；**每天付账后只充一次**；电流转换器输入**每日 kJ**；普通电池在线备电 + 日结单块最多充 1/4；**无限电池没有实时容量，只有日输出额度（基础 12，强化 +10/次，无上限），睡觉结算读一次、不缓存**；proxy 先验算 demand；日结顺序：**无限电池吃 demand → 转换器补差 → 柜先满 → 电池逐块倒（1/4 或满）**；实际电网抽取**次日结算**。
- **能源不足**：机器直接不跑，没有欠费账本。
- **电池槽**：16 个槽前到后，不均摊；抽电/充电都是前到后；充电倒红酒（单块 1/4 或满），预算空了后面的没有；普通/无限/一次性/转换器按 tag 分类，违禁品不搞超级科技。
- **美术**：参考 AE2 风格自己画；不要直接抠 AE2 图标/素材，注意 LGPL 与商标。
