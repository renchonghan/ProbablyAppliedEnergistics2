## 0. 一句话

**可能是应用能源2** 是给《深空当铺》的**机架式仓储 / 物流 / 订单自动化**：

> **3×3 机架阵列 + 3×3 核心设备 + PoE 干线 + 虚拟网络搬运 + 订单生产。**
> 线缆只负责电、数据、调度；**不做实体货运**。

## 2. 核心原则

1. **虚拟逻辑，不做实体货运**  
   有网 = 物品可寻址；搬运 = 直接库存事务；没有实体管道、没有物品飞行、没有每帧物流模拟。  
   AE2 在大服能活下来，就是因为它没有实体管道；我们照这个底层哲学做。

2. **线缆必须有，但线缆不运物品**  
   线缆是拓扑、供电、数据、物流调度；真正的物品在端点由模块直接搬。  
   玩家接线的快乐来自**路径、容量、冗余、剪线、过载**，不是看物品在管子里飞。

3. **空间是浪漫，不是菜单**  
   ME 控制器/控制终端/电力模块/磁盘驱动器是 **3×3 真实物品**；机架也是 **3×3 外观，内部 2 列 × 4 行 = 8 槽**；磁盘、线缆是 **1×1**；原版机器进机架后槽内忽略形状。  
   机柜阵列排开、带灯、带端口、带线——这是 AE 玩家的浪漫。  
   不统一的异形格子才是华容道；统一的 3×3/1×1 是机房平面图。

4. **虚拟磁盘只存“可拆解后的叶子物品”**  
   入库 = 拆解计划 → 写盘 → 校验 → 删除原物品；失败不删除原件。  
   枪/带插件/容器等复杂物品**自动拆成部件/内容物**；不想拆就用真实盒子，不要扔进虚拟存储。  
   原子/密封/任务物品直接拒绝虚拟存储，提示“请用真实容器”。

5. **自动化必须消耗资源**  
   补货/生产必须检查配方、原料、能量；不能凭空 clone。  
   否则就是无限复制机，房租、检查、经济全崩。

6. **订单是玩家唯一需要理解的东西**  
   玩家只负责下单；拆配方、备料、排队、生产、送货由机房完成。  
   AE2 的递归工单可以做，但要藏在“订单卡”后面。

## 3. 硬件形态

### 3.1 机架（Rack）——扩展机器区

- **3×3 真实物品**，固定占用基础背包网格；内部孔位是 **2 列 × 4 行（8 槽）**。
- **UI 直接复用工具箱**：8 个 `GameSlotInventory`，`SetColumns(2)`，同样的槽底/标签；工具箱是 3×3，机架是 2×4。
- 内部 **8 个万能槽（universal bays）**，不是 8 个 1×1 格子：
  - 每个槽可以放**一台原版机器**（不管它原本是 3×2 还是 2×2，槽内忽略形状）；
  - 也可以放一台 **Disk Drive（3×3 算一个 bay）**——组合式机架，服务器里再塞服务器。
- **防套娃**：机架不能塞机架；ME 控制器/控制终端/模板控制器/电力模块/数据转移机/原子分离机不进屋，基础设施保持在机柜阵列外部。
- 机架就是“扩展机器区”：原版机器塞进去后，**插适配器才被网络供电/喂料/收产物**；没插适配器仍按原版周期运行/手动使用。
- 机器存进磁盘 = **停机归档**；放回机架也只是“放置架”，除非电池槽插了 **ME 适配器**。
- **只有插了 ME 适配器、且频道已连接的机架机器才被网络接管**；按机器类型自动走 **Virtual（虚拟产线）** 或 **Monitor（监控托管）**；没插/没频道 = 纯放置/手动。
- 左/右 **PoE 端口**，状态灯；机架有供电预算/负载/维护费。
- **一个已连接的 ME 适配器（虚拟/监控）= 一个通道**；机架扫描内部适配器数量并向线缆申请总量；常规线 8、致密线 32（AE2 原版）。
- 相邻 3×3 机架形成 **Rack Array（机柜阵列）**；视觉上连成一排，可以有共享背板/管理加成，但每个机架仍然占 3×3。

### 3.2 ME 控制器（3×3）+ 控制终端（3×3）

- **ME Controller 3×3**：网络大脑；一个网络一个；负责 PoE 分配、能量缓冲、网络负载/端口上限。被拆/移走就断网。
- **Control Terminal 3×3**：容器/终端 UI；可以有多个；通过 PoE 连接控制器。
  - **Storage 页**：虚拟库存视图（搜索/过滤/取出/即产；库存 0 只有模板命中才显示幽灵）；
  - **Inbox 页**：真实容器页，专门收投放，扔进来立刻转移走；
  - **Daily Plan 页**（每日基础备料；客户一次性订单后期再加）。
- 控制器和终端分开，都是 3×3；这样机柜阵列里每一台都是同样的 footprint。

### 3.3 电力模块 / ME 能源柜（3×3，巨型 UPS）

- **3×3 真实物品**，存 kJ，供给网络。
- **16 个普通电池槽 + 1 个电流转换器专用槽**。
- 电池行为：
  - **普通电池**：在线备电；柜内 kJ 不够时，直接扣电池的电；每日结算可充电，**单块最多充总容量的 1/4**（防超级快充偷鸡）。
  - **无限电池**：**没有实时容量**，只有“每天能出多少电”的**日输出额度**（`HYPERTECH_BATTERY_OUTPUT_INT`）：基础 **12**，强化一次 **+10**，**无上限**；睡觉结算时读一次当前值，玩家当天强化过就按新值算；**不缓存**；只参与日结，白天不放电。
- **有且只有一次充电机会：每天付账后**；白天不能补电。
- 柜容量：默认 **255 kJ**，可强化到 **65,535 kJ**（巨大 UPS）。
- 电流转换器面板设置“每日输入 kJ”；到账日抽这么多电存进柜里。
- 电用完 → 机器停；没有欠费账本。
- 统一 3×3：控制器、终端、电力模块、磁盘驱动器排在一起，视觉上是一排整齐的机柜。
- **槽位检查**：原版电流转换器和电池都属于 `power_source_item`，所以：
  - 转换器槽只接受 `CURRENT_CONVERTER_TAG`；
  - 16 个电池槽只接受 `power_source_item` 且**不是**电流转换器；
  - 用 `mayInventoryAddItemFunc` 分流，避免电池插进转换器槽/转换器占电池槽。

### 3.4 线缆（PoE Trunk，1×1）

- **1×1 真实物品**，物理摆在机架/控制器/终端/电力模块/磁盘驱动器之间。
- PoE 干线 = **电 + 数据 + 物流调度**；**不运物品**。
- 有等级/容量/成本；可以剪断、改线、看负载。
- 过载 = 机架掉电/设备离线；冗余/双 uplink 有意义。
- 机房用 **uniform grid**（机架外观 3×3、内部 2×4 槽；核心设备 3×3；线缆/磁盘 1×1），不玩异形拼图。
- **已定**：放在基础背包网格；不是专用机房页。空间成本保留。

### 3.5 机架槽位（universal bays）

| 槽位内容 | 说明 |
|---|---|
| **原版机器** | 任意机器物品，槽内忽略形状；保留自己的窗口/周期/配方 |
| **Disk Drive** | 组合式机架：3×3 驱动器算 1 个 bay，里面再插 16 张磁盘 |

> 机架是“机器扩展区”，磁盘不直接插机架；但 **Disk Drive 可以作为组合式机架的一个 bay 整体塞进去**，形成“机架里放驱动器”的组合式机架。  
> 机架 8 个万能槽只混装**原版机器和 Disk Drive**；没有扩展卡；机器不按形状占位，避免把机架变成华容道。  
> 导入/导出/生产调度/安防是**控制终端/网络功能**，不是机架扩展卡，不占槽。  
> 技术上：槽位用 `GameSlotInventory`（单槽容器，不按网格形状检查）；没插适配器的机器按原版周期运行；插了适配器的机器按 profile 走：确定性机器纯计算，水培/RAS/宿主屠宰机仍跑原版 cycle，只做 monitor/白名单物流。

### 3.6 磁盘驱动器（Disk Drive，3×3）

- **3×3 真实物品**，外观和机架同 footprint；内部 **2 列 × 8 行 = 16 个磁盘槽**，每个槽插一张 **1×1 磁盘**。
- 可以整体放进机架的一个万能槽（3×3 算 1 bay）；**不能再塞进另一个 Disk Drive**，只存磁盘。
- 磁盘分两种，**完全独立**：
  - **Solid Storage Disk / 固体磁盘**：只存物品条目；
  - **Fluid Storage Disk / 液体磁盘**：只存液体条目。
- 两种磁盘**独立强化、独立容量、独立索引/字节**，不能混用、不能混算；Disk Drive 16 个槽可以混插，但账本分开。
- **容量从 16 索引 / 256 字节开始，用材料逐级强化到 512 索引 / 65,535 字节**；升级保留内容。下表对固体/液体各自适用。
- 建议档位：

| Tier | 索引 | 字节 | 约等于 物品（8/byte） | 约等于 液体（100ml/byte） |
|---|---:|---:|---:|---:|
| T1 | 16 | 256 | 2,048 | 25.6 L |
| T2 | 32 | 1,024 | 8,192 | 102.4 L |
| T3 | 64 | 4,096 | 32,768 | 409.6 L |
| T4 | 128 | 16,384 | 131,072 | 1,638.4 L |
| T5 | 256 | 32,768 | 262,144 | 3,276.8 L |
| T6 | 512 | 65,535 | 524,280 | 6,553.5 L |

- 强化材料用游戏现有材料（电路/模块/高科技电子等），具体配方 Phase 0 定；升级后**内容保留**，不重写条目。
- 驱动器把磁盘接入网络；控制终端的 Storage 页显示所有磁盘的聚合索引。
- 磁盘是 1×1 物品；驱动器是 3×3，保持机柜阵列统一 footprint。

#### 字节与索引（已定）

- **固体**：8 个物品 = 1 byte；一组 64 = 8 bytes（AE2 味）。
- **液体**：100 ml = 1 byte；1 L = 10 bytes（可控，不做无限水库）。
- 65,535 bytes ≈ 524,280 个物品，或 ≈ 6,553 L 液体；后续可调，但先按这个走。
- **索引**：固体 = `identifier + 关键 feature 签名`；液体 = `类型 + 纯度档位`（1%/5% 一档，避免无限索引）。
- **没有原子分离机时，不同纯度/混合液体不合并**：各自是实例/条目，512 索引自己承担。
- 有原子分离机后，入库自动分离/合并，按下文物质守恒规则结算。

#### 原子分离机（Atomic Separator，3×3）

- **3×3 Hero 设备**；液体、混合液、带纯度的固体（奥克莫西、梦尘等）都能拆。
- 可以插原版的 **效率 / 质量 / 速度模组** 强化；具体换算待定，但**效率模组会大幅降低耗电**。
- **没有分离机**：纯度物质不合并，各自占索引/实例。
- **有分离机**：每次存入自动分离，消耗电量；纯物质合并，剩余纯度留一个余数固体，杂质变液体原料。
- **水回收**：RAS 脏水/废物 → 液体磁盘 → 分离机 → 纯水回灌；物质守恒，滤芯变成可选。
- **物质守恒**（纯度用整数 0–100 计算，避免浮点漂移）：
  - `totalPure = Σ purity_i`，`n` = 输入件数；
  - `full = totalPure / 100`，`rem = totalPure % 100`；
  - `impurity = n * 100 - totalPure`；
  - `rem > 0`：输出 1 个纯度为 `rem` 的余数固体，吸收 `min(100 - rem, impurity)` 的杂质；剩余杂质 → 液体；
  - `rem == 0`：全部杂质 → 液体。
- 例子：
  - **3×75%** → `2×100%` + `1×25%` + `0 L` 杂质；
  - **4×75%** → `3×100%` + `1000 ml` 杂质液体；
  - **3×50%** → `1×100%` + `1×50%` + `1000 ml` 杂质液体。
- 1 单位杂质默认 = **1000 ml**（可调）；杂质都能装瓶，连淀粉也算液体，进液体磁盘单独存。
- 名字：**原子分离机 / Atomic Separator**；你叫“原子分离剂机”也行。

### 3.7 数据转移机（Data Transfer Machine，3×3）

- **3×3 真实物品**，带电池槽 + 两个磁盘槽。
- 用途：**磁盘对磁盘搬数据**，换硬盘/迁移/整理时用。
- 原则：**移动，不是复制**；源盘条目成功写入目标盘后才删除源条目，失败不丢数据。
- 消耗电池 kJ；理论用不到，但换盘/扩容时很舒服。
- 3×3 统一尺寸，和驱动器/机架排在一起。

### 3.9 移液枪（流体工具，3×2）

- **3×2**，和打标机（Labeler）同款 footprint；不是 1×1 小卡片，是一把真工具。
- 注册为 **TOOL**，兼容工具箱：放进 toolbox 的 1–9 号槽（**初始解锁 3 个，最多 9 个**），用 1–9 快捷键装备，再对目标容器/机器使用。
- 一把枪两个模式：**吸液**（目标容器/机器 → 枪内储罐/网络）和 **加液**（枪内储罐/网络 → 目标容器/机器）；右键/快捷键切换。
- 如果更喜欢仪式感，也可以拆成两把 3×2 的吸液枪/加液枪；两者都保持打标机尺寸。
- 枪有内部储罐（ml）、液体类型、纯度/污染标记；可以在控制终端/Inbox 排空或补充。
- 可以给水培、净化器、水箱、反应器直接加液；也可以从顾客的容器里吸液（如果游戏允许）。
- 风险与乐子：
  - 加错液体/污染批次会掉品质；
  - 吸到违禁化学品/赃物液体可能被检查；
  - flavor text 建议写：**“本来是加油枪，现在给你加纯水。不要对顾客使用。”**
- 这是“显性物品”的一部分：玩家能记住“我有吸液枪/加液枪”，而不是只有抽象模块。

### 3.10 ME 适配器（1×1，电池槽；一物品双 profile）

- **1×1**，和电池同类型，插进机器的电池槽；**一个物品，两种 profile**，不再做独立的服务适配器。
- **插上 + 频道已连接**才被网络接管；没插/没频道 = 纯放置/手动。**1 个适配器 = 1 个通道**（虚拟和监控都算）。
- **Profile 自动判断**（玩家不用选；适配器 UI 显示 badge）：
  - **虚拟产线（Virtual）**：确定性合成机器。机器是能力 token；生产/合成按配方 + 属性纯计算，**不跑真机器 cycle**，不调用 `onCycleEnd*`；输入/输出物品由 1 Hz 对账挪进磁盘。
  - **监控托管（Monitor）**：有生命/环境状态的机器（水培、RAS、宿主屠宰机）。**原版 cycle 照跑**；网络只做监控、供电、白名单物流；不虚拟产物、不推进生长。
  - **未知机器 → 默认监控/只读**，绝不偷偷虚拟化。
  - 识别优先级：`HYDROPONIC_MACHINE_TAG` / `RAS_TAG` / `AUTO_BUTCHER_TAG` → Monitor；有配方能力且无生物状态 → Virtual；两者都像 → Monitor（保守）。
- **供电**：适配器本身是 `power_source_item`，网络从 ME 能源柜给它补内部 buffer。虚拟 profile 用 buffer 满足机器供电检查；监控 profile 直接用这个 buffer 给真 cycle 供电。**不可手动充电**。
- **监控 profile 的物流**只碰白名单槽：
  - 水培：水槽、种子槽、产出格；补水、补营养、补种、收菜；生长中的种子和模块不动。
  - RAS：水槽、饲料槽、4 个滤芯槽（可选）、屠宰输出；补水、排废/换水、补饲料、收死鱼和鱼获；有原子分离机时走水循环，不强制换滤芯；活鱼不动。
- **宿主屠宰机**：Auto Butcher 没有电池槽，通常挂在 RAS/动物笼的屠宰槽；RAS 的适配器同时监控宿主和里面的屠宰机。动物笼没有电池槽，MVP 先不做，后面加专用服务口。
- flavor text：**“ME 适配器。插上：会算的当产线，会活的当监控。”**

### 3.11 电流转换器（1×1，ME 能源柜专用插槽）

- **1×1**，插在 ME 能源柜的**专用插槽**，不占机器电池槽。
- **输入功率 UI**（类似鉴定价值界面）：输入的是**每日 kJ**，不是即时功率。
- **每日结算**：每天付账后，抽 `dailyKJ` 存进能源柜，上限 = 柜容量（255 → 65,535）。
  - **普通电池**：每日结算可充电，单块最多充总容量的 **1/4**；白天柜内不够时也**直接扣电池**（在线备电）。
  - **无限电池**：没有实时容量，只有日输出额度（基础 12，强化 +10/次，无上限）；睡觉结算时读一次当前额度（当天强化也生效），**不缓存**；只参与日结，白天不放电。
  - 没有电池：按 `dailyKJ` 从店内电力/账户结算，走 `CURRENT_CONVERTER_SERVICE`/每日电费。
- **日结算法（先验，倒红酒）**：
  1. proxy 镜像机器状态，先验算出次日生产总耗电 `demand`；
  2. **无限电池按日输出额度先吃 demand**（睡觉结算时读一次当前额度；当天强化按新值；不缓存）；
  3. demand 超过无限电池 → **电流转换器补差额**，转换器 `dailyKJ` 相应减少；
  4. 转换器剩余预算：**先把 ME 能源柜补满**；
  5. 柜满后，**挨个给充电电池倒电**：单块本次最多充 `总容量 × 1/4`，或者直接倒满，先到先停；有剩余预算继续下一块；
  6. 记录转换器**实际从电网抽取的 kJ**；这笔账单**次日结算**。
- **250 例子**：无限电池日额度 200，全部用掉；转换器补 50；剩 150 → 柜子缺 100（满），充电电池 700/800 再倒 50 → **750/800**；转换器实际抽 **200**，次日账单 200。
- **150 例子**：无限电池日额度 200，用掉 150（剩 50 日额度，不是容量）；转换器抽 150 → 柜子缺 100（满），再给充电电池倒 50 → **750/800**；次日账单 150。
- 账单 = `dailyKJ` × 当前转换率；复用 `CurrentConverterHelper` 的 rate/日结逻辑。
- 如果 `dailyKJ` > 柜容量：UI 直接限制/提示；如果电源不足：按可用量充，显示缺口。
- **200KJ 卡死模组罚金**也从 ME 能源柜扣；柜内不足 200KJ → 拒绝拆解/入库。
- 机器/机架白天只吃能源柜，不再逐台找店电；能源柜一天就这一口电。

#### 16 个电池槽：顺序与分类

- **顺序**：从前往后（slot 0 → 15），**不搞均摊**；抽电和充电都是前到后。
- **充电（倒红酒）**：每块最多充 `总容量 × 1/4` 或直接倒满；预算空了，后面的电池没得喝。
- **电池分类（按 tag）**：
  - **可充电普通电池**：`power_source_item` 且不是 disposable/hypertech/converter；在线备电；日结可充，单块 1/4 或满。
  - **无限电池**：`HYPERTECH_BATTERY_TAG`；没有实时容量，只有日输出额度；日结读一次；不参与普通充电/在线放电。
  - **一次性电池**：`POWER_SOURCE_ITEM_DISPOSABLE_TAG`；只放电、不充电；违禁品标记不改变物理，不生成无限电。
  - **电流转换器**：`CURRENT_CONVERTER_TAG`；只进专用槽，不进 16 电池槽。
- **防超级科技**：违禁品/一次性电池不得被当成无限电池或可充电电池；未知电池类型 → 拒绝充电，最多按一次性放电处理。

### 3.12 模板控制器（Pattern Controller，3×3）

- **3×3 网络设备**，和 ME 控制器/控制终端/电力模块/磁盘驱动器同 footprint；放在机柜阵列外部，不塞进机架。
- **UI 参考原版储藏区（扩建）/ Storage Bay (Extended)**：**5 个大页**（5 个 tab），每页 **17×10 格**；双击页签可改名，最多 12 字符；直接复用 `StorageExpansionHelper` / `storage_bay_large` 的页面布局，不另造一套。
- **模板（Pattern）是 2×1 真实物品**，放进页面格子里：
  - 空白模板可叠放；编码后变成唯一实例，不再合并。
  - 每页 17 宽、模板 2 宽 → 每行 8 个、每页 80 个、**5 页约 400 个模板**；17 宽会剩 1 列空位，不硬塞。
- **合成模板编码**：把空白模板放进模板控制器页面，拖入/使用一个真实物品或液体样本；控制器记录：
  - 输出签名（`identifier` + 关键 feature/纯度/品质）；
  - 绑定的一条游戏配方（recipe ID / 输入 / 机器类型 / 能耗 / 时间）；
  - 每次生产的数量。
  - 样本不消耗；有多条配方时让玩家选；无配方、或输出是无法复现的实例物品 → 拒绝编码。
  - 过程模板编码见 3.13：不写配方，也不写屠宰设置。
- 编码后的模板显示输出图标/名称；右键可清除回空白模板。模板被取出、控制器离线/被拆 → 对应幽灵和自动生产立即消失。
- **模板控制器只存模板，不存物品**；模板索引按网络聚合。
- **频道**：模板控制器**不占频道**（频道仍然只按 ME 适配器计数），但计入网络负载；多个模板控制器可以并存，输出签名重复时按槽位顺序取第一个有效模板，重复项标记“重复”但不删除。
- **唯一白名单**：只有模板里记录的输出才允许幽灵、自动补货、自动生产/订单；没有模板的物品在库存耗尽后从网络里消失。详见 4.3 和 5。

### 3.13 过程模板（Processing Pattern）

- 和合成模板同一 **2×1 Pattern** 物品、同一模板控制器页面；编码后显示“过程模板”图标/颜色。
- **不改屠宰机设置**：`AUTO_BUTCHER_*` 由玩家在原版 UI 设置；网络只读/尊重，**不写入、不临时覆写、不恢复**。模板只记录“投什么鱼 + 输出白名单”。
- 编码时直接看原版屠宰机 UI 的当前设置；模板只记录输入鱼条件 + 输出白名单，不保存设置快照，只按原版设置判断“这条鱼会不会被加工”。
- 模板记录：输入鱼种/条件（species/weight/age/roe 等）+ 输出白名单；编码时拖入一条鱼样本记录条件，样本不消耗。
- **常驻屠宰（理想）**：按当前原版设置喂合格鱼，让屠宰机自己触发加工；网络只负责投喂与收产物。
- **加急单（最低）**：只影响投喂选择，选最小/最年轻且当前设置仍会接受的鱼；不改设置。没有合适鱼 → 订单卡显示“缺少材料：需要 ≥600g 罗非鱼（当前设置），当前最大 450g”，不静默替换。
- 如果原版设置是 harvest off/不接受，网络不强行加工；订单卡显示“屠宰机设置不接受”，让玩家自己去改。
- 加急单期间常驻屠宰让路/暂停**投喂**，不改设置；预留鱼不被常驻自动化抢。
- **触发方式 Phase 0 验证**：可能是鱼直接丢到 Auto Butcher 身上（`InitDropOnButcher` / `ButcherDropped`），也可能是宿主 RAS/笼子的 `onCycleEndLate` 自动 `Run`；先按原版路径走，不自己造 cycle。
- **投喂路径**：按原版可触发方式（直接丢到 Auto Butcher / 放进宿主鱼缸），让原版逻辑决定是否加工；网络不直接调用 `TryButcherFish`、不伪造 cycle。
- **产物收集**：屠宰机输出格是 10×10，产物单一（肉/鱼卵/皮/尸体）；1 Hz 对账递归扫描宿主屠宰机的内部库存，只收输出白名单，绝不收输入鱼/屠宰机本体/工具。
- 过程模板的输出也可以出现在 Storage 幽灵列表；点幽灵 = 排 process job，不是瞬间出肉。
- 多个屠宰机/模板按输出签名去重，沿用 3.12 规则。

### 3.14 监控托管（Monitor Profile）

- 只用于水培/RAS/宿主屠宰机；UI 是**概况页**，不是控制台；手动设置回原版机器窗口。
- 宿主屠宰机只显示状态/投喂/收产物，**绝不改 `AUTO_BUTCHER_*`**；设置由玩家在原版窗口改。
- 每台机器一张 monitor 卡：
  - 水培：水量/水质、营养范围、作物/进度、ETA、电、警报。
  - RAS：水量/废物%、饲料 kcal、过滤/分离循环（4 个滤芯可选）、鱼群/阶段、饥饿/健康、ETA、电、警报。
- **无滤芯水循环（推荐）**：RAS 水槽的脏水/废物由适配器抽到液体磁盘 → 原子分离机分离（耗电）→ 纯水回 RAS；物质守恒，滤芯变成可选。分离机离线/没电时才需要滤芯，monitor 报“过滤/分离循环”状态。
- **基础维护**：固定阈值——缺水补水、废物高就排废/换水、缺饲料补饲料、有产物就收（只收产出/死鱼/鱼获，不动活鱼）；有分离机时优先水循环，滤芯只作后备；最多一个“自动维护”总开关，不做每槽规则。
- **RAS 水预算（核心报警）**：
  - `currentNeed = Σ 当前阶段水需`（按原版算，鱼苗组不乘组数）；
  - `adultNeed = Σ 组数 × 成体阶段水需`（鱼苗/鱼卵按组数乘，不能只看当前）；
  - 水箱固定 **12L**；RAS 扩宽/加高只加鱼格，不加水量。
  - 黄：`adultNeed > 80% × 12L`；红：`adultNeed > 12L` 或 `currentNeed > 实际水量`。
  - 同时报警：成体占格 > 鱼缸格；废物 >3%/8%；滤芯 0/4（无分离循环时）；饲料 <3 天；电力缓冲低；未收集鱼卵/繁殖开启。
- **减密单**：红警报给“排减密单”按钮，复用过程模板的加急投喂；只选最小/最年轻且当前屠宰设置会接受的鱼苗/幼鱼，不改设置；不自动杀，玩家确认；无合适鱼 → 缺少材料。
- 不自动替玩家决定种什么/养什么/杀什么；monitor 只报警、建议、执行固定维护。

## 4. 控制终端交互

### 4.1 Storage 页

- 打开后是巨大的虚拟库存视图。
- 每个条目右下角角标：
  - 普通物品：`x12`；
  - 液体：`12.5 L` / `12,500 ml`；
  - 0 且模板命中：灰色 `0` 幽灵条目，条目仍然可点；
  - 0 且没有模板：**条目不显示**，搜索也搜不到。
- 有货：左键取 1，右键取一组。
- 0（仅模板命中）：合成模板 = 消耗能量**即刻生产**；过程模板 = 排 process job，显示 ETA/缺料。
- 液体按**纯度/品质分行**，不要把不同纯度的水混成一个数字。
- 搜索/过滤/排序是 UI 层；底层是磁盘条目（虚拟存储），不是真实物品槽。
- 物品入库 = 拆解计划 + 快照 → 写盘 → 校验 → 删除原物品；库存归零时删除磁盘条目并释放索引/字节；只有模板命中的输出由模板重新生成幽灵。

### 4.2 Inbox 页（投放页）

- 一个**真实容器页**，专门收玩家扔进来的东西。
- 扔进来 → 生成拆解计划/快照 → 写入磁盘 → 校验 → 删除原物品 → 槽位清空。
- 转移失败（满/不可存/缺配方/序列化失败）→ 物品留在 Inbox，红色状态提示，**不删除**。
- 等于给控制终端装了一个“单向漏斗页”。
- 实现要原子：先写盘成功，再从 Inbox 删除；转移中加短暂 lock，别让玩家 Alt 拿走，避免复制/丢失。

#### 入库拆解规则

- **简单物品**：1 个条目。
- **枪/带插件**：拆成枪身、枪管、弹匣、枪托、下挂、特殊槽等；每个部件独立条目。
- **容器/背包**：内容物递归入库；空容器作为独立条目（或按规则返回）。
- **液体容器**：液体进液体磁盘，空容器进固体磁盘；混合液先是一个“混合液”条目，原子分离机再拆。
- **机器**：不拆，整机 Instance 存；存进去不工作、不耗电；要成为**虚拟产线/监控托管**必须放进机架 + 插 **ME 适配器** + 频道连接。
- **原子/密封/任务物品**：拒绝虚拟存储，提示“请用真实盒子/容器”，不要强行 snapshot。
- **卡死模组**：带 `MODULE_STUCK_TAG` 的机器入库时自动拆模组，**从 ME 能源柜扣 200KJ**；柜内不足 200KJ 就拒绝，防免费拆 bug。
- **不想拆**：把东西放真实盒子/背包，不要扔进 Inbox；虚拟存储不保留复杂物品树。
- **拆解预览/日志**：Inbox 显示“将拆成 N 个条目”；任一步失败都不删除原件。
- **价值**：部件按游戏原值；不复制价值、不凭空生成，拆解是玩家选择。

### 4.3 幽灵物品（Ghost Item）

- **幽灵只来自模板控制器**：只有输出被模板记录、且当前库存为 0（包括从未存过）的条目才显示幽灵。
- **没有模板的物品：库存耗尽后从 Storage 页消失**；磁盘条目删除，释放索引/字节，不显示 0，也不能点击即产。玩家要恢复它，必须重新放入实物或先编码模板。
- 幽灵**不占磁盘索引/字节**，不是磁盘条目，也不是 0 个的真实物品；它由模板索引实时生成。
- `mayInventoryRemoveItemFunc = false`，任何快捷键都拿不走；不会卡上柜台。
- 点击幽灵 → 合成模板按配方生产；过程模板排 process job（真机器执行，显示 ETA/缺料）；成功 → 写入磁盘条目（或生成真实物品，如果该条目是真实槽模式）；失败 → 幽灵继续保留，tooltip 报错。
- 模板被取出/控制器离线 → 幽灵立即消失；库存 > 0 的条目仍然正常显示，等它耗尽后再按模板规则决定是否消失。
- 幽灵物品不进 Inbox；它只存在于 Storage 页的“0 库存 + 模板命中”条目。
- 幽灵按**输出签名**精确匹配：纯度/品质/关键 feature 不同的产物不会互相点亮。

### 4.4 快捷键（实测行为）

游戏实测（用户开游戏确认）：

| 键 | 行为 |
|---|---|
| **Alt** | 在最前端打开窗口/容器与柜台之间扔；没有打开窗口时，在仓库（背包）与柜台之间扔 |
| **Ctrl** | 在仓库与最前端打开窗口之间扔；没有打开窗口时，扔上柜台 |
| **柜台** | = 交易区 |

- 打开控制终端时把它 `ToFront()`，确保它是“最前端窗口”，Alt 的语义稳定是“面板 ↔ 交易区”。
- **Inbox 页/真实物品**：游戏原生 quick-move 生效。
- **Storage 页虚拟条目**：自定义列表，需要在点击处理里自己复刻 Alt/Ctrl；幽灵物品锁死，不响应。
- 如果 Storage 页是自定义虚拟列表（不是真实 `GameItemElement`），就调用 `ModHelper.MoveItemToFrontCounter(item)` / `GraphUtils.TryAcceptOnce(...)` 复刻同样行为。
- 扔错地方无所谓：顶多进仓库，手一拖就回来。

### 4.5 自动补货

- 监听取出/消耗 → 触发补货；**只有模板控制器里存在对应输出的条目才允许补货**。
- 没有模板：库存耗尽就消失，不自动生产；要恢复自动补货，先把物品编码成模板。
- 补货必须：查模板 → 检查配方 → 检查原料 → 检查能量 → 成功才写入磁盘条目。
- **过程模板的补货是排产**：检查真机器/ME 适配器/合适鱼/水/饲料，排 process job；不是瞬间补，也不是凭空出肉。
- 补货模式：
  - **能量即产**：有电有料，立刻补；
  - **夜间批产**：闭店后按配额补；
  - **自动补货开关**：每个条目单独开关。
- 补货目标/上限可设；避免玩家不想补的东西被补。

### 4.6 实例物品与校验（不能合并）

> **这不是 edge case，这是“合并了会被玩家打”的 case。**

典型例子：**无限强化电池**（`HypertechBatteryHelper`）：

- `HYPERTECH_BATTERY_TAG`；
- `HYPERTECH_BATTERY_OUTPUT_INT`（基础 **12**，每次强化 +10）；
- `HYPERTECH_BATTERY_UPGRADE_COUNT_INT`（强化次数）；
- 还能继续叠 `unitValue`。

如果把这种电池当成普通“物品类型”合并，所有电池会变成一个条目，强化等级直接蒸发。必须按**实例**存：

| 存储类别 | 规则 |
|---|---|
| **Type-stackable** | 无耐久、无充能、无新鲜度、无内容物、无可变参数的简单可堆叠物品；同 `ItemKey` 合并数量 |
| **Instance** | 有耐久/磨损/充能/新鲜度/纯度/品质/内容物/序列号/可变参数/永久强化的物品；**一件一个索引**，完整快照，不合并。机器也走 Instance（整机、含电池槽/模块），存盘后**停机** |
| **Refuse** | 原子/密封/任务/未知模组物品、**活鱼/鱼苗/生长中植物**，或快照校验失败；拒绝虚拟存储，用真实盒子/鱼缸/水培机 |

规则：

- **任何耐久/可变参数/永久强化 tag**（`DURABILITY_TAG`、`MAX_DURABILITY_TAG`、`DURABILITY_FAKE_TAG`、`HAND_CONDITION`、`FRESH_FOOD_TAG`/`FRESHNESS_TAG`、`CHARGE_*`、`power_source_item_energy`、`HYPERTECH_BATTERY_*`、`MACHINE_*`、`MODULE_*`、`TURBO_*`、`CURRENT_CHARGE_TAG` 等）→ **Instance**，一件一个索引。
- **新鲜度是固定值**：`FRESHNESS_TAG` 在生成时定死，不随时间腐烂；但不同值仍是不同实例（荧光莓/Bloomberry 酿酒要用），不能合并。
- **判断口径**：玩家会关心“这一件和那一件不一样”的，就不合并；耐久、磨损、充能、新鲜度（固定值）、纯度、品质、内容物、机器状态都算。
- **机器**：不拆，整机 Instance 存；存进去不工作、不耗电；要成为**虚拟产线/监控托管**必须放进**机架** + 插 **ME 适配器** + 频道连接。快照包含电池槽/模块；快照失败就拒绝。
- **生物边界**：活鱼、鱼苗、生长中的植物 **Refuse**；干种子（带基因）、鱼卵、鱼获/肉可以按 Instance 存；水按液体条目/纯度存。
- `Instance` 条目保存：`identifier`、`unitCount`、全部 tag、`itemFeatures`、`itemTypes`、`unitValue`、`lateUnitValue`、`shape/state`、子物品（仅机器）等；数值用精确类型，不截断。
- **入库校验**：序列化 → 反序列化成临时物品 → 对比实例签名（所有 tag/feature/数值/子物品）；不一致就拒绝，原件留在 Inbox，提示“请用真实盒子”。
- **保守默认**：只有白名单里的简单物品允许 Type-stackable；其余一律 Instance 或 Refuse。宁可拒绝，不可静默合并。
- 512 索引是硬上限；每个独特耐久物品/电池/机器占 1 个索引，装不下就换磁盘或放真实盒子，**不合并**。

## 5. 订单与自动合成

### 5.1 订单卡

```
┌ 订单 #42 ─────────────────┐
│ 客户：Vera                 │
│ 要：3x 净水                │
│ 库存：1 / 3                │
│ 缺：2                      │
│ 可做：是（缺 1 个空瓶）     │
│ 模板：合成 / 过程 / 缺失     │
│ 预计：2 周期 / 40 kJ       │
│ [一键下单]  [加急]          │
└────────────────────────────┘
```

- **一键下单**：有料就做，没料就自动拆子订单。
- **加急**：合成模板花供能矩阵/涡轮加速器的 kJ，立刻完成一个周期；过程模板只切投喂选择（最低可接受输入），**不改屠宰设置**，按真实机器排产。
- **失败**：明确告诉玩家缺模板、缺机器/服务、缺合适鱼、缺原料、缺电、缺配方。

### 5.2 四层结构

1. **模板（Pattern）**
   2×1 真实物品；**合成模板**绑定输出 + 配方；**过程模板**绑定输入条件 + 输出白名单（只读原版设置，不改写）。模板是自动生产的唯一白名单。

2. **配方卡（Recipe）**
   `输入 → 输出`，绑定机器类型、时间、能耗；合成模板引用它，不另存一份大 JSON。

3. **订单（Job）**
   数量、期限、优先级；递归展开依赖；中间产物放网络里；子订单可并行。缺模板的中间产物直接报错，不偷偷合成。

4. **执行器（虚拟产线 / 监控托管 / 供能矩阵）**
   虚拟产线按合成模板纯计算；监控托管按过程模板驱动真机器；供能矩阵只加速虚拟计算；没有机器/合适输入就排队或报错。

### 5.3 配额生产 = 定时订单

- **客户订单**：一次性，做完结束；
- **配额订单**：保持“水 30、餐 20、零件 10”，缺了自动补；
- 配额生产只接受**模板里已有的输出**；没有模板的货不会自动补；
- 过程模板的配额是**排产**，ETA 按真实机器；不会瞬间补鱼/肉；
- 两者共用同一个订单引擎，只是 `once` vs `repeat`。

### 5.4 实时性

- 商店侧没有实时机器 tick；**虚拟产线**纯计算，**过程模板**走真机器周期，订单卡显示 ETA。
- `MachineTurboBoosterAdv.BoostMachine()` 只用于真实机器/兼容路径；虚拟产线用供能矩阵加速**虚拟计算**；供能矩阵不虚拟生物过程。
- 合成配方 + 原料 + 机器属性齐了 → 立刻算出产物；过程模板等真实机器完成/收割。
- 供能矩阵充好 → 加速虚拟计算/瞬间完成；过程模板只能靠真机器（或后续生长加速器）推进。
- 没电/没机器/没合适鱼/缺配方 → 排队或缺料，订单卡显示具体原因；
- 闭店后 → 批量计算/排产，早上报告“完成/缺料/缺电”。

### 5.5 每日计划（Daily Plan）

- 控制终端独立一页 **Daily Plan**：设定明天每种货的目标库存（水 30、餐 20、零件 10……）。
- Daily Plan 只能选**模板里已有的输出**；合成模板即刻/批量，过程模板排产并显示 ETA；没有模板先编码，否则计划报错。
- 闭店/夜间按计划补货/生产；早上报告完成/缺料/缺电。
- 客户采购、枪匠订单可以复用同一个 job 引擎，但**MVP 先做每日基础备料**，一次性客户订单后期再加。
- 后期可用 Harmony 在客户议价界面加“一键下单”按钮，但不是 MVP 主入口。

### 5.6 虚拟产线 + 监控托管 + 1 Hz 对账

- **只有插了 ME 适配器且频道已连接的机架机器才被网络接管**；没插/没频道 = 纯放置/手动。
- **Virtual profile（确定性机器）**：纯计算；机器只是能力 token；输入/输出清进磁盘；不跑真 cycle；不做虚拟副本。
- **Monitor profile（水培/RAS/宿主屠宰机）**：原版 cycle 照跑；网络只做 monitor、供电、白名单物流；**不虚拟产物、不推进生长**。
- **1 秒对账一次**，只扫带适配器的机器：
  - Virtual：生产输入/输出槽 → 直接挪磁盘；
  - Monitor：只碰白名单服务槽（水/种子/饲料/滤芯（可选）/产出/屠宰输出）；活鱼、生长中的植物、模块、工具不动；
  - 不删除、不吞物品；未知机器布局只写日志。
- **过程模板由真实机器执行**：1 Hz 只负责喂料/收货/监控，不调用 `onCycleEnd*`、不模拟生长；没有合适输入 → 缺料。
- 同步机器属性：强化模组、配置 tag、效率/质量/速度等；玩家改机器配置后，下次 1 Hz 同步生效。

## 6. 网络 / PoE

- **PoE 干线** = 电 + 数据 + 物流调度命令；**没有物品包**。
- **频道按 AE2 原版**：**1 个已连接的 ME 适配器（虚拟或监控）= 1 个通道**；常规线 8，致密线 32。
  不做轮椅：8/32 台适配器机器封顶，超过就加线/加控制器，不能一根线无限挂。
- **模板控制器不占频道**：频道只按 ME 适配器计数；模板控制器计入网络负载，不参与 8/32 分配。
- **机架申请逻辑**：
  1. 扫描机架内部机器；
  2. 统计插了 ME 适配器的机器数量（虚拟/监控都算）；
  3. 向线缆申请**这个总量**的频道；
  4. 按槽位顺序（0 → 7）分配：前 N 个连接，后面的标记“无频道”；
  5. 没抢到频道的适配器**按没插适配器处理**：不虚拟生产、不监控、不服务，纯放置/离线。
- **不是整架罢工**：只有超出频道容量的适配器不连接；已连接的机器继续跑，状态灯显示已连接/无频道。
- 机架/控制终端/线缆组成网络图；线缆剪断 = 网络断开。
- 电力预算/物流负载另算，不跟频道混：
  - 电力决定虚拟机器能不能跑；
  - 频道决定多少台适配器机器能接入；
  - 物流负载决定同时跑多少订单。
- 过载 = 设备离线/掉电；冗余/双 uplink 有意义。
- 后期可加子网/VLAN、无线终端、跨区链路；不做 P2P/量子/空间存储的 1:1 复刻。

## 7. 非目标（明确不做）

- **不做实体货运/物品管道/物品飞行**；
- 不做世界方块/线缆方块网格；

- 不改商店布局/核心循环/议价 UI；
- 不新增顾客精灵图/阵营；
- 不复制 AE2 代码/贴图/文本；
- 不把游戏反编译代码/本地化表提交到 GitHub。

- **组合式机架**：Disk Drive 可以算 1 个 bay 塞进机架；机架不能塞机架，控制器/终端/模板控制器/电力模块/数据转移机/原子分离机不进屋。
- **机架 UI**：直接复用工具箱格子（8 个 `GameSlotInventory`，`SetColumns(2)`，2×4），只是工具箱是 3×3。
- **模板控制器**：3×3 网络设备，放在机柜阵列外部；UI 参考原版储藏区（扩建）/ `Storage Bay (Extended)`，**5 个大页**、每页 **17×10**、页名 12 字符；模板 **2×1**；每页 80 个、5 页约 400 个；不占频道、计网络负载；可多个，按输出签名去重。
- **模板**：2×1 真实物品；空白可叠，编码后 Instance；合成模板绑定输出签名+配方，过程模板绑定输入条件+输出白名单（只读原版设置）；样本不消耗；无配方/不可复现的实例输出拒绝编码；**模板是幽灵/补货/订单/自动生产的唯一白名单**。
- **幽灵门控**：只有模板命中的输出在库存 0 时显示幽灵；无模板的物品耗尽后删除条目、释放索引/字节；幽灵不占磁盘索引/字节。
- **频道**：**1 个已连接的 ME 适配器（虚拟/监控）= 1 通道**；常规线 **8**，致密线 **32**；机架扫描内部适配器数量并申请总量，按槽位顺序点亮；没抢到的适配器按未插处理，不虚拟/不监控/不服务。
- **字节**：固体 **8 个 = 1 byte**；液体 **100 ml = 1 byte**；磁盘从 **16 索引 / 256 bytes** 起，材料强化到 **512 / 65,535**，升级保留内容。
- **入库拆解**：枪/容器等复杂物品自动拆；机器整机 Instance 存但停机；原子/密封/任务物品拒绝，用真实盒子。
- **实例规则**：任何耐久/可变参数（`DURABILITY_*`、`HAND_CONDITION`、`FRESH_FOOD_TAG`/`FRESHNESS_TAG`（固定值，不腐烂）、充能、纯度、内容物、机器状态）→ **Instance**，一件一索引；只有无状态白名单耗材合并；索引满了换盘/真实盒子，不合并。
- **卡死模组**：带 `MODULE_STUCK_TAG` 的机器入库时自动拆模组，**从 ME 能源柜扣 200KJ**；柜内不足就拒绝；预付费/电流转换器实现 Phase 0 确认。
- **ME 适配器（一物品双 profile）**：1×1 电池槽；插上+频道连接才接管；**1 适配器 = 1 通道**。确定性机器 = **Virtual**（纯计算，不跑真机器 cycle、不调用 `onCycleEnd*`，1 Hz 清输入/输出）；水培/RAS/宿主屠宰机 = **Monitor**（原版 cycle 照跑，网络只监控/供电/白名单物流）；未知机器默认 Monitor/只读。没有独立服务适配器。
- **过程模板**：2×1 Pattern 的第二种编码；**不改屠宰机设置**，只读/尊重 `AUTO_BUTCHER_*`；只决定投什么鱼 + 输出白名单；常驻=按当前设置投喂，加急=选当前设置仍接受的最小鱼；缺合适鱼直接显示缺少材料；输出格递归扫描，只收白名单；过程模板输出幽灵点击=排产，不是瞬间出肉。
- **监控托管**：水培/RAS 只做概况页，不做复杂控制台；固定阈值自动维护；宿主屠宰机设置只读，不改写；RAS 水预算 = 当前/成体预测（鱼苗按 `组数 × 成体水需`），报警爆缸、空间、废物、过滤/分离循环、饲料、电力、鱼卵；红警报可排减密单。
- **无滤芯水循环**：RAS 脏水/废物抽到液体磁盘 → 原子分离机 → 纯水回灌；物质守恒，滤芯可选；只有分离机离线/没电才需要滤芯。
- **生物库存边界**：活鱼、鱼苗、生长中植物 **Refuse**；干种子/鱼卵/鱼获/肉可以按 Instance/类型存；水按液体条目/纯度存。
- **每日计划**：控制终端单独一页 **Daily Plan**，做每日基础备料；客户一次性订单后期再加。
- **原子分离机**：只影响液体/纯度物质；没有它不允许合并；有它后入库自动分离并耗电；物质守恒，杂质进液体磁盘。
- **电力合同**：ME 能源柜 **16 电池槽 + 1 电流转换器槽**，容量 255 → 65,535 kJ；**每天付账后只充一次**；电流转换器输入**每日 kJ**；普通电池在线备电 + 日结单块最多充 1/4；**无限电池没有实时容量，只有日输出额度（基础 12，强化 +10/次，无上限），睡觉结算读一次、不缓存**；proxy 先验算 demand；日结顺序：**无限电池吃 demand → 转换器补差 → 柜先满 → 电池逐块倒（1/4 或满）**；实际电网抽取**次日结算**。
- **能源不足**：机器直接不跑，没有欠费账本。
- **电池槽**：16 个槽前到后，不均摊；抽电/充电都是前到后；充电倒红酒（单块 1/4 或满），预算空了后面的没有；普通/无限/一次性/转换器按 tag 分类，违禁品不搞超级科技。
- **美术**：参考 AE2 风格自己画；不要直接抠 AE2 图标/素材，注意 LGPL 与商标。
